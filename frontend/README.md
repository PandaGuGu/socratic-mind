# frontend

**这里只有设计原型，没有前端工程。** 实际界面是服务端托管的静态页面，位于
`backend/psych-app/src/main/resources/static/`，访问 `/room/`、`/knowledge/`、`/account/`、`/internal`。
不引入构建链，是因为页面数量少、只需要少量交互，加一层打包只会增加部署复杂度。

## 原型

| 文件 | 是什么 | 什么时候用 |
|-|-|-|
| `preview/world-demo.html` | 房间（默认界面）→ 说话 → 纸片飞出窗 → 点窗看泡泡 | **默认界面的设计基线**；动效与叙事看这个 |
| `preview/ui-demo.html` | 三栏文档式界面（知识问答 / CBT / 记录） | 长答案排版；也是"不接受隐喻"时的降级方案 |

试的顺序：点墙角的小人 → 选一句话发出去（纸片飞向窗外，窗外多一颗星，石子前进）→
点窗户（泡泡是历次对话）→ 点任一泡泡（纸片浮起，可读当时的对话）。

两份原型共用 [UI 设计规范](../docs/05-规范/02-UI设计规范.md) 的 token，不另起一套。

## 原型与实装的关系

`world-demo.html` 的逻辑已搬进后端并接上真实接口，**原型保留作设计基线，不再加交互**；
要改交互，改 `static/room/index.html`。设计意图与数据映射见 [界面与交互](../docs/03-设计/04-界面与交互.md)。

## 三条前端纪律

1. **不写状态。** 只有"发消息"与"确认"能推进流程，不得直接改阶段或任何字段。
2. **`stage` 按枚举渲染。** 新增阶段时前端应"不认识就降级展示"，而不是崩。
3. **不隐藏"我不知道"。** 证据不足是正常业务结果，不渲染成错误页。
