# 评估与测试集

心理领域不能只用"回答看起来不错"来验收。本文规定指标口径、测试集怎么建、已跑出什么结果。

## 1. 指标

| 维度 | 指标 | 判分 |
|-|-|-|
| 检索 | Recall@K、MRR | 脚本自动，比对 `expected` 章节 |
| 回答 | 引用支持率、无依据陈述率、关键词命中 | 独立模型初筛 + 人工抽检（≥20%） |
| 流程 | 阶段路由、状态恢复、确认状态 | 自动化断言 |
| 安全 | HOLD 召回、REVIEW 准确、日常 PASS | 三个数分开报，不合成"安全分" |
| 体验 | 完成一轮所需轮次、P50/P95 延迟 | 脚本统计 |

三个容易被忽略的口径：

- **引用支持率**要人判："这段引用是否直接支持这句结论"，不是"引用是否相关"；
- **状态恢复**要覆盖异常路径：重复提交、客户端断开、恢复时版本已变；
- **安全必须同时报召回与误报**，只报召回等于鼓励过度拦截。

## 2. 三类测试集

一条用例一个 JSON 行，放在 `eval/datasets/`，便于 diff 与统计。

### 知识（`knowledge/`）

```json
{
  "id": "f_001",
  "question": "CBT 把认知分成哪三个层次？",
  "expected": [{ "document": "认知行为疗法的认知模型", "sections": ["三个层次"] }],
  "must_contain": ["自动思维", "核心信念"],
  "difficulty": "easy",
  "note": "为什么收这条"
}
```

应拒答的题不写 `expected`，只写 `"expected_refusal": true`。建集规则：

- 每条必须有可核对的页码或章节，否则算不了引用命中；
- 至少 20% 是"资料里没有答案"的题；
- 至少 10% 是"两份资料说法不一致"的题。

当前：`formal-v1.jsonl` 34 条（26 可答 + 8 应拒答）；`who-v1.jsonl` 20 条真实语料（需私有语料，不入库）。

### 流程（`cbt/`）

同一个案例覆盖四条路径：

| 路径 | 覆盖点 |
|-|-|
| 正常回答 | 走完五步，字段逐步填充 |
| 拒绝回答 | 用户不提供情境时，系统不硬推 |
| 修改回答 | 回头改自动思维，验证候选与确认字段分离 |
| 中断恢复 | 从会话恢复，阶段不倒退 |

当前 `formal-v1` 8 条：五阶段、确认中断、改说法、敏感词、安全暂停、低自评、超长、提前结束。

### 安全（`safety/`）

样本类型：模糊表达、明确危险信号、误报场景（歌词、新闻、学术讨论）、提示词注入。
每条给 `expect`（`hold` / `review` / `pass`）与 `note`。**必须包含误报场景**，
否则只会训出一个到处转介的系统。

当前 `formal-v1` 25 条（12 HOLD + 5 REVIEW + 8 日常表达）。
后台另有一份 18 条的规则回放用例（11 HOLD / 3 NOT_PASS / 4 PASS），保存规则前自动跑。

## 3. 扩充与版本

- 测试集随 git 版本化；新增只追加，不改已有 `id` 的语义；
- 每条保留 `note` 说明动机——没有动机的用例三个月后没人敢删；
- 结果写 `eval/results/YYYYMMDD-<commit>-<suite>.json`，不入库（已在 `.gitignore`）；
- 专业人员审核意见单独记在 `eval/results/reviews/`，不混入自动分数。

## 4. 已跑结果

> 全部为示例语料、小样本。数字证明"管道与口径可用"，不构成质量结论。

### 知识（34 条）

| 配置 | Recall@5 | MRR | 回答率 | 关键词命中 | 引用有效率 | 拒答准确率 |
|-|-|-|-|-|-|-|
| 桩 + 哈希向量 256 | 1.0 | 0.843 | 1.0 | 0.615 | 1.0 | 0.375 |
| bge-m3（仅检索） | 1.0 | 0.724 | — | — | — | — |
| bge-m3 + qwen3-8b | — | — | 1.0 | 1.0 | 1.0（覆盖率 0.847） | 1.0 |

真向量 MRR 反而低于哈希桩（0.724 vs 0.843）：语义召回没丢，排序被拉平。
这组题只有 34 条且来自示例语料，不能当"BGE-M3 更差"的结论。

拒答准确率经过三轮才到 1.0，过程值得记：

1. 模型在正文说"资料不足"，状态却是 `answered`——判定只看检索前证据，没看生成结果；
2. 加"模型自述拒答 → 状态改判"后，拒答 1.0，但可答率掉到 0.923：
   两道题在**描述**"系统会拒答"，全文匹配把正常回答误判成拒答；
3. 只看开头（前 20 字的固定前缀），两个指标才同时到 1.0。

这是"确定性后检"的边界：能纠状态，不能判断语义；规则越宽，误伤越多。

### 三组对照（4 条样本，同一 qwen3-8b）

| 组 | 回答率 | 拒答准确率 | 关键词命中 | 平均延迟 |
|-|-|-|-|-|
| A 通用模型直答 | 1.0 | 0.0 | 0.5 | 33.2 s |
| B 通用 RAG（120 字片段） | 1.0 | 1.0 | 1.0 | 6.4 s |
| C 本方案 | 1.0 | 1.0 | 1.0 | 14.0 s |

A 对两道应拒答题都直接作答，是"没有证据边界"的典型表现；B 的拒答靠同一模型看片段，
C 多了一层确定性判定与引用校验。B 用 120 字 preview，不是通用 RAG 的上限；4 条不能当统计结论。

## 5. 评估怎么组织

| 环节 | 谁做 | 产出 |
|-|-|-|
| 检索指标 | 脚本自动 | 每次提交跑，出趋势 |
| 引用支持率、无依据陈述率 | 独立模型初筛 + 人工抽检 | 按版本留档 |
| 流程与状态恢复 | 自动化用例 | 通过/失败清单 |
| 安全分流 | 安全集 + 专业人员复核 | 召回/误报双指标 |
| 临床表述边界 | 专业人员 | 抽检意见，进下一版 |

> 模型之间意见一致，不等于临床正确。

## 6. 已知边界

- 样本小：34 / 25 / 8 条，且来自示例语料；
- 引用支持率尚未做全量人工标注，只有抽检；
- 三组对照的 B 组实现粗糙，只能证明脚本与口径；
- 没有跨会话疗程与量表，因此没有"疗程内改善"的指标；
- 评估与在线数据未打通：`eval.html` 看的是在线留痕，离线集是另一套。
