# 接口契约

## 1. 通用约定

- Base path：`/api`。版本放在 header `X-Api-Version: 1`，不改路径。
- 身份：除 `POST /api/cbt/sessions` 外，所有 `/api/cbt/**` 请求必须带 `X-User-Token`。
  首次创建会话时由响应头回发令牌；带令牌再开会沿用同一身份。令牌由服务端 HMAC 签发，
  客户端无法伪造（[ADR-0007](../04-adr/ADR-0007-会话归属与内部接口鉴权.md)）。
- 令牌两版：`v1` 设备令牌（未登录），`v2` 账号令牌（登录后）。同一个请求头，区别在可见范围：
  `v2` 能多看"已认领到账号"的会话（[ADR-0009](../04-adr/ADR-0009-账号作为叠加层.md)）。
  `v2` 签了 `token_epoch`：改口令、退出其他设备、重置口令会让旧令牌下一次请求 401。
- 内部接口与知识库写入需 `X-Internal-Token`，与用户令牌互不通用。
- 时间一律 RFC3339，UTC。
- 未知字段忽略；缺必填字段返回 422。

### 三条硬约束

1. **前端不能写状态。** 只有"发消息"与"确认"能推进流程。
2. **`stage` 是枚举，不是自由字符串。** 前端按枚举渲染，不认识就降级展示，不要做字符串匹配。
3. **知识问答与 CBT 不共用会话。** 会话表、身份范围、权限检查都分开。

## 2. 错误码

| code | HTTP | 含义 | 前端处理 |
|-|-|-|-|
| `UNAUTHORIZED` | 401 | 缺少或无效令牌 | 重新开一轮，静默换取新令牌 |
| `NOT_FOUND` | 404 | 会话不存在**或不属于当前身份**（刻意不区分） | 回列表 |
| `CONFLICT` | 409 | 状态冲突，例如重复确认 | 刷新状态 |
| `TOO_MANY_REQUESTS` | 429 | 触发限流（消息 60/分钟、开新会话 30/小时/IP） | 提示稍后再试 |
| `INVALID_ARGUMENT` | 422 | 参数缺失或格式错误 | 就地提示 |
| `SESSION_ENDED` | 409 | 会话已结束，拒绝继续写 | 引导新建 |
| `DUPLICATE_MESSAGE` | 200 | `clientMessageId` 重复，返回上次结果（不算错误） | 忽略 |
| `GRAPH_STAGE_INVALID` | 409 | 当前阶段不接受该输入 | 提示重试 |
| `EVIDENCE_INSUFFICIENT` | 200 | 知识问答证据不足（业务状态，非异常） | 正常展示"暂无法回答" |
| `SAFETY_HOLD` | 200 | 安全分流触发，普通流程暂停 | 展示转介信息，锁定输入 |
| `MODEL_UNAVAILABLE` | 503 | 上游模型不可用 | 重试 + 降级提示 |

`EVIDENCE_INSUFFICIENT` 与 `SAFETY_HOLD` 用 200，因为它们是**预期内的业务结果**。
用 4xx 会让前端把"系统诚实地拒答"渲染成错误页。

### 一轮的请求与响应

```json
// POST /api/cbt/sessions/{id}/messages
{
  "sessionId": "cbt_...",
  "message": "最近我总是因为学习任务感到焦虑",
  "clientMessageId": "msg_001"
}
```

```json
{
  "sessionId": "cbt_...",
  "stage": "PROBLEM_IDENTIFICATION",
  "stageLabel": "情境",
  "visibleIndex": 0,
  "status": "awaiting_user",
  "response": "最近一次让你产生这种感受的具体事情是什么？",
  "awaitingConfirmation": false,
  "safetyStatus": null,
  "confirmedThought": null,
  "distortions": [],
  "moodSeries": [4],
  "crisis": null
}
```

| 字段 | 说明 |
|-|-|
| `stage` | 枚举，见下；大写 |
| `stageLabel` | 中文标签，仅供展示，不要拿它做逻辑 |
| `visibleIndex` | 0–4 对应五颗石子；安全暂停与结束为 -1 |
| `status` | `awaiting_user` / `awaiting_confirmation` / `safety_hold` / `ended` / `content_blocked` |
| `response` | 本轮面向用户的话术 |
| `awaitingConfirmation` | 是否停在确认中断点 |
| `safetyStatus` | `hold` / `review` / 空 |
| `confirmedThought` | 用户确认过的说法；拒绝回答时为 null |
| `distortions` | 候选认知偏差，最多 3 个 |
| `moodSeries` | 用户自己点的分数序列，后端不插值 |
| `crisis` | 仅安全暂停时非空：热线、联系人、可复制的话 |

`status=content_blocked` 表示命中敏感词被整句拦下：流程不推进，换个说法就能继续。

### stage 枚举

`PROBLEM_IDENTIFICATION` · `COGNITIVE_EXTRACTION` · `COGNITIVE_REVIEW` · `INTERVENTION_DECISION` ·
`BEHAVIORAL_EXPERIMENT` · `PRACTICAL_PROBLEM_SOLVING` · `CONDITION` · `ACTION_CONFIRM` ·
`ACTION_REVIEW` · `SESSION_SUMMARY` · `SAFETY_HOLD` · `ENDED`

前五个可见阶段与三个可选分支的语义见 [流程与状态 §2](02-流程与状态.md)。

### 分页

```
GET /api/cbt/sessions/page?limit=40&cursor=<上一页的 nextCursor>
```

- 按创建时间倒序；`limit` 1–50，默认 20。
- 游标是 `(createdAt, id)` 的 base64，不是 offset：一边翻一边新开一轮时，offset 会重复或跳过。
  客户端原样带回即可；无效游标返回 422，不静默回到第一页。
- 可见范围与列表接口一致。

### 一次性分享

| 方法 | 路径 | 说明 |
|-|-|-|
| POST | `/api/cbt/sessions/{id}/share` | 需要本人令牌；`{ttlHours}` 1–168，默认 24；返回 `{path, expiresAt}` |
| DELETE | `/api/cbt/sessions/{id}/shares` | 撤回未打开的链接 |
| GET | `/api/share/{token}` | **公开**，只能成功一次，之后 410 |

返回记录本身（阶段、想法链、情绪、偏差、消息），**不含联系人电话、内部轨迹、可枚举的会话 id**。

## 5. 账号

不登录时接口行为与无账号版本完全一致。账号接口都在 `/api/auth` 下，
除 `/me` 与 `/claim` 外都返回 `X-User-Token` 响应头（同时也在响应体的 `token` 字段里）。

| 方法 | 路径 | 说明 |
|-|-|-|
| POST | `/api/auth/register` | 注册；返回令牌、`pendingClaims`、一次性 `recoveryCode` |
| POST | `/api/auth/login` | 登录；错误不区分"邮箱不存在"与"口令错" |
| GET | `/api/auth/me` | 已登录返回账号，否则 `200 {signedIn:false}` |
| POST | `/api/auth/claim` | 显式认领本设备的匿名会话 |
| POST | `/api/auth/password` | 改口令；旧令牌（含其他设备）立即 401 |
| POST | `/api/auth/logout-all` | 推进令牌代数，其他设备下线 |
| POST | `/api/auth/recover` | 用一次性恢复码重置口令 |
| POST | `/api/auth/recovery-code` | 重新生成恢复码，旧码作废 |
| POST | `/api/auth/delete` | 注销；先解除认领，再删账号 |
| GET | `/api/auth/contact` | 读取账号上的紧急联系人；没填过返回空对象 |
| PUT | `/api/auth/contact` | 保存或清空；只做字符清洗，不做格式校验 |

```json
// POST /api/auth/register
{ "email": "you@example.com", "password": "至少 8 位", "displayName": "可不填，≤32 字" }

// 200
{ "token": "v2....", "account": { "id": "acc_...", "email": "you@example.com" },
  "pendingClaims": 3, "recoveryCode": "ABCD-EFGH-JKLM" }
```

- 邮箱统一转小写；重复注册、弱口令、格式错误都返回 422，限流 20 次/小时/IP。
- `pendingClaims` 是"可以"认领的条数，不会自动认领；共享设备的后来者不接手前一个人的记录。
- **没有 `/logout`**：令牌是无状态签名串，服务端没有可删的会话记录，
  写一个"返回 200 但什么也不做"的退出接口等于骗人。退出由客户端丢弃令牌完成，账号页会把设备令牌换回来。
- 注销是另一件事：它删账号，令牌真的失效。

## 7. 内部接口

按用途分组，全部要求 `X-Internal-Token`（或组织模式下的操作者会话 + CSRF）：

| 组 | 路径前缀 | 用途 |
|-|-|-|
| 会话与轨迹 | `/api/internal/sessions`、`/overview`、`/safety/review` | 列表、逐轮轨迹、待复核队列 |
| 规则与用例 | `/api/internal/safety/rules`、`/cases`、`/limits` | 安全规则、回放用例、运行参数 |
| 配置历史 | `/api/internal/config/*` | 快照、对比、回滚 |
| 知识库 | `/api/knowledge/*` | 检索调试、入库、审核 |
| 词库 | `/api/internal/lexicon` | 整表读写、试跑、回滚、恢复基线 |
| 画布 | `/api/internal/flow/*` | 草稿、发布、多库、起点 |
| 输出策略 | `/api/internal/policy`、`/guard/audit` | 禁句与阈值、拦截审计 |
| 评测 | `/api/internal/eval/*` | 四格指标、badcase 池、确定性抽样 |
| 审核 | `/api/internal/reviews` | 规则/词库/流程/策略/限流/会话六类留痕 |
| 账号与模型 | `/api/internal/accounts`、`/ai` | 只读账号视图、延迟与 token |

字段与门禁见 [内部后台](../03-设计/03-内部后台.md)。

## 8. 流式

当前所有接口返回**整段 JSON**，没有 SSE。

计划中的边界（实现时按此约束，不要前端改状态）：

| 事件 | 内容 | 谁改状态 |
|-|-|-|
| `token` | 文本增量 | 不改状态 |
| `state` | 阶段、status、待确认项 | 后端节点写入，前端只读 |
| `done` | 本轮结束 + 引用 | 后端落库后发出 |
| `error` | 错误码 | 后端 |

本地 Ollama 单轮 20–30 秒，流式是明显的体验缺口；但补它不能以"前端能写状态"为代价。
