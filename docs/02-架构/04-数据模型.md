# 数据模型

事实来源是两份建表脚本，本文只解释语义与取舍：

- `backend/psych-infrastructure/src/main/resources/db/schema-cbt.sql`：会话、账号、组织、评测、限流
- `backend/psych-infrastructure/src/main/resources/db/schema-pg.sql`：知识库与 pgvector

两份脚本都写成幂等的 `CREATE TABLE IF NOT EXISTS` + `ADD COLUMN IF NOT EXISTS`，
PostgreSQL 与 H2（PostgreSQL 兼容模式）执行同一份文件。没有引入 Flyway：表不多，脚本可重放。

## 1. 五个域

| 域 | 表 | 说明 |
|-|-|-|
| 知识域 | `kb_document` / `kb_chunk` / `kb_evidence` / `kb_document_review` | 入库、检索、审核的事实来源 |
| 会话域 | `cbt_session` / `cbt_message` / `cbt_turn` | 用户可见的对话与逐轮决策依据 |
| 账号域 | `app_account` / `share_link` | 可选账号与一次性分享 |
| 组织域 | `org_tenant` / `org_team` / `org_member` / `org_session` / `org_login_attempt` | 租户、团队、操作者与登录留痕 |
| 运行支撑 | `eval_query_log` / `eval_badcase` / `rate_limit_counter` | 在线评测与限流计数 |

三条边界不可混：

1. 知识域的表只由入库流程写入，业务代码只读；
2. 会话域以用户可见事实为准，与运行时快照冲突时以会话域为准；
3. CBT 会话与知识问答不是同一张表——知识问答不留会话历史。

## 2. 知识域

| 表 | 一行是什么 | 关键字段 |
|-|-|-|
| `kb_document` | 一份资料 | `status`（draft/reviewing/published/archived）、`external_key`、`content_hash`、`acl_scope`、`deleted_at` |
| `kb_chunk` | 一个父块或子块 | `parent_id`、`document_version_id`、`title_path`、`page_start/end`、`embedding`、`is_parent` |
| `kb_evidence` | 一条结构化证据 | `condition_text`、`population`、`intervention`、`recommendation_strength`、`evidence_quality`、`limitations`、`review_status` |
| `kb_document_review` | 一次审核签字 | `document_id`、`version`、`reviewer`、`decision`、`acl_scope` 快照、`reviewed_at` |

四个字段各对应一类真实事故：

| 字段 | 没有它会怎样 |
|-|-|
| `content_hash` | 每晚全量同步都会重新切分与向量化，CPU 烧光 |
| `external_key` | 改标题就变成新文档，旧块永远留在索引里 |
| `acl_scope` | 权限只能在生成后删引用，越权内容已进模型上下文 |
| `deleted_at` | 删除只能物理删，误删不可恢复 |

`embedding` 维度随模型走：哈希桩 256，BGE-M3 1024。切换模型不能复用旧列，
要么清空重建，要么用 `VectorDimensionMigrator` 重建列与 HNSW 索引后重新嵌入。

## 3. 会话域

| 表 | 一行是什么 | 谁读它 |
|-|-|-|
| `cbt_session` | 一次会话的当前状态：停在哪个阶段、确认过什么、安全状态、联系人、情绪序列 | 流程续跑、会话列表、记录页 |
| `cbt_message` | 一句对话（`role` / `stage` / `content` / `at`） | 记录页、窗外回看、导出 |
| `cbt_turn` | 一轮的决策依据（动作、阶段迁移、安全规则、模型来源、拦截规则、耗时） | 内部控制台、审计 |

三张表分开的理由：只存运行时快照会出现"能续跑但查不到当时说了什么"。
只存消息则会出现"看得到对话，说不出第几轮为什么被拦住"。

两个刻意的取舍：

1. **列表字段用 TEXT 存 JSON**（`mood_points` / `distortions` / `evidence_for`）。
   它们是一次会话内的短列表，拆表只增加 join；要按证据检索时再拆。
2. **整轮覆盖写**：每次保存先删该会话的消息与轨迹再重建。会话是几十条量级，
   简单换来"内存与库永远一致"；要追加式写入时换实现即可，接口不变。

## 4. 归属：设备与账号

```
app_account（账号，可空）
      ▲ account_id
      │
cbt_session ── user_id ──▶ 设备身份（令牌签出来的）
      │
      ├── share_link（一次性链接，只存 token 的 SHA-256）
      └── cbt_message / cbt_turn
```

- `user_id` 是**设备**归属，登录不改写它；`account_id` 是"还能看它的账号"，可空。
  关系与理由见 [ADR-0009](../04-adr/ADR-0009-账号作为叠加层.md)。
- 账号表不含任何心理字段：注销账号不需要连带处理会话，会话也可以完全不属任何账号。
  注销是两步：先 `account_id` 置空，再删账号，同一事务。
- `token_epoch` 用于吊销：改口令、退出其他设备、重置口令时 +1，旧令牌下一次请求 401。
- `share_link` 只存 `token_hash`，不存明文；已用、过期、撤回都表现为不可用。
- 账号表另有 `contact_name` / `contact_phone` / `contact_relation`：登录后在账号页填一次，
  新开的一轮自动带上；会话里仍可单独覆盖，两边互不写回。

## 5. 组织域与登录留痕

`org_tenant` / `org_team` / `org_member` 解决"谁签的字"：写操作要求操作者令牌，
署名取自会话而不是输入框（[ADR-0010](../04-adr/ADR-0010-组织域与操作者身份.md)）。

| 表 | 用途 |
|-|-|
| `org_member` | 口令摘要、`session_epoch`、所属团队 |
| `org_session` | HttpOnly 会话，登出即删 |
| `org_login_attempt` | 登录成功与失败都留痕，失败按账号限流 |

## 6. 运行支撑

| 表 | 用途 | 取舍 |
|-|-|-|
| `rate_limit_counter` | 固定窗口计数，按 key 原子 upsert | 多实例共享；窗口边界可能瞬时放行 2 倍配额 |
| `eval_query_log` | 每轮问答的留痕 | 写入是旁路，失败不影响回答 |
| `eval_badcase` | 拒答、引用无效、管道异常的样本池 | 拒答不等于错误，只是值得看一眼 |
