# UI 设计规范

> 风格代号：**纸本 + 工具**（Editorial × Quiet Utility）。
> **两套界面，不强行统一**：前台知识问答用纸本阅读语言，房间保留沉浸式场景；后台运营侧用工具控制台语言。
> 知识库后台是唯一的内容型例外——它做的是“读资料、核对出处”，所以按纸本语言实现，不套用会话控制台。
> 桌面网页优先，浅色为默认，深色跟随系统。
> 对应实现：`/knowledge/`（用户知识问答）、`/internal/knowledge.html`（知识库后台）、`/room/`（房间，单独维护）。
> 上位依据：[方案对比 §6 短板](../01-概览/03-方案对比.md)、[ADR-0004 不诊断](../04-adr/ADR-0004-产品边界停在不诊断.md)。

## 0. 两套界面，不强行统一

| | 前台用户侧 | 后台运营侧 | 知识库后台（内容型例外） |
|-|-|-|-|
| 谁用 | 普通用户 | 运营 / 审核 / 开发 | 知识运营 |
| 看什么 | 内容、出处、下一步 | 状态、队列、参数 | 资料、切分、命中、出处 |
| 语言 | 纸本 + 阅读：衬线标题、脚注引用、无阴影 | 工具 + 控制台：高密度表格、状态徽章、绿色强调 | 纸本 + 工具：阅读为主，审核动作为辅 |
| 实现 | `/knowledge/`（纸本）；`/room/`（沉浸式，单独维护） | `/internal/index.html`、`flow.html`、`policy.html`、`settings.html` | `/internal/knowledge.html` |

两套只共享三条信息原则：**引用可核对、状态显式、不做风险分级**。组件、配色、字号体系各走各的。
强行统一的结果是：用户嫌后台味太重，运营嫌阅读页太慢。

### 0.1 实施状态（2026-11-20）

- `/knowledge/`：已按本规范实现提问、回答、脚注引用、右侧出处、证据不足态与移动端。
- `/internal/knowledge.html`：已按设计稿实现纸本阅读 + 审核动作。
- `/room/`：保留沉浸式房间；左上角新增返回知识主页的箭头；对话与引用面板的可读性 pass 另行安排。
- 会话、流程、策略、规则四个后台页：保持工具型控制台，不改。

## 1. 为什么是这套视觉

三条来自产品本身的约束，不是审美偏好：

| 约束 | 视觉后果 |
|-|-|
| 差异化在"出处可查证"，不在"会共情" | 引用的视觉重量必须接近正文，不能做成装饰性标签；正文要能长时间读 |
| 状态是显式字段（`currentStage`），不是模型记忆 | 步骤必须常驻可见，不藏在菜单里 |
| 销售对象是机构，验收看"记录能否交给老师/咨询师" | 记录页要像文档，不像聊天截图；必须能打印 |

因此：**衬线体负责"这是读物"，等宽字体负责"这是状态"，无衬线体负责"这是操作"**。三者分工固定，不混用。

## 2. 色彩

一个强调色，全站只有这一个。心理类产品最容易犯的错是"淡蓝 + 淡紫渐变"，那套语言在说"我很温柔"，而我们要说的是"我说的话可查"。

### 2.1 Light（默认）

| Token | 值 | 用途 |
|-|-|-|
| `--paper` | `#FAF8F4` | 页面底色（米白，非纯白） |
| `--surface` | `#FFFFFF` | 卡片、输入区 |
| `--ink` | `#1F1D1A` | 正文 |
| `--ink-2` | `#57534C` | 次要正文、用户发言 |
| `--ink-3` | `#8A857B` | 标签、元信息、占位符 |
| `--rule` | `#E3DED3` | 0.5px 分隔线 |
| `--rule-strong` | `#CFC8B9` | 强调分隔、输入框描边 |
| `--accent` | `#B06A3B` | 强调：步骤当前项、引用线、上标 |
| `--accent-ink` | `#8C4E28` | 强调色上的文字（满足对比度） |
| `--tint` | `#F2E6DA` | 强调色的淡底（当前步骤、引用块） |
| `--refer` | `#9B3B32` | 仅用于安全转介，**不得用于普通错误** |

### 2.2 Dark

| Token | 值 |
|-|-|
| `--paper` | `#191715` |
| `--surface` | `#211E1B` |
| `--ink` | `#EDE8DE` |
| `--ink-2` | `#B5AFA3` |
| `--ink-3` | `#857F74` |
| `--rule` | `#33302B` |
| `--rule-strong` | `#45403A` |
| `--accent` | `#D9915E` |
| `--tint` | `#2B2521` |

深色不是把浅色反相：底面偏暖（褐灰），避免纯黑带来的"终端感"。

### 2.3 使用规则

1. 强调色面积不超过单屏 5%。超标就说明用错了——它标的是"当前位置"和"证据来源"，不是装饰。
2. 不设"success / warning / danger"三色系统。业务上只有三种可辨状态：**正常、证据不足、需要转介**。前两种靠文字与留白表达，只有转介用 `--refer`。
3. 不用颜色区分"我已读 / 未读""高 / 中 / 低"——本产品不做风险分级（ADR-0004）。

## 3. 字体与字阶

| 角色 | 字体栈 | 字号 / 行高 | 字重 |
|-|-|-|-|
| 页面标题 | 衬线 | 26px / 1.4 | 500 |
| 区块标题 | 衬线 | 18px / 1.5 | 500 |
| 引导语（Agent 的话） | 衬线 | 15px / 1.9 | 400 |
| 正文 | 无衬线 | 13.5px / 1.75 | 400 |
| 用户发言 | 无衬线 | 13.5px / 1.7 | 400 |
| 标签 / 元信息 | 无衬线 | 11px / 1.4，`letter-spacing: .06em` | 400 |
| 页码 / 步骤号 / 数值 | 等宽 | 11px，`font-variant-numeric: tabular-nums` | 400 |

字体栈：

```css
--serif: "Source Han Serif SC", "Noto Serif SC", "Songti SC", "SimSun", serif;
--sans:  "PingFang SC", "Source Han Sans SC", "Microsoft YaHei", system-ui, sans-serif;
--mono:  "JetBrains Mono", "SF Mono", Consolas, monospace;
```

规则：

- 只有两个字重：400 和 500。**不用 600/700**——中文粗体在屏上会糊，靠字号和留白建立层级。
- 衬线体只用于"系统对你说的话"和标题。所有操作元素（按钮、输入、标签）一律无衬线，避免"古籍感"。
- 中文衬线在 Windows 上回退到宋体时可读性下降，正文长度超过 200 字时改用无衬线（知识页长答案的正文段落用无衬线，只有引导语与摘要用衬线）。

## 4. 间距、圆角、描边

| 项 | 值 |
|-|-|
| 间距序列 | 4 / 8 / 12 / 16 / 24 / 32 / 48（只用这七档） |
| 圆角 | 4px（标签、上标）/ 8px（卡片、输入）/ 999px（仅状态胶囊） |
| 描边 | 0.5px `--rule`；强调时 0.5px `--rule-strong`；引用左线 2px `--accent` |
| 阴影 | **不用**。层级靠底色差与分隔线 |
| 渐变 / 模糊 / 发光 | **不用** |

## 5. 布局（桌面）

```
┌──────────────────────────────────────────────────────────┐
│ 顶栏 56px：产品名 · 场景切换 · 主题切换                    │
├────────────┬───────────────────────────┬─────────────────┤
│ 左栏 240px │ 主区 max 720px            │ 右栏 280px      │
│ 步骤栏 /   │ 正文、对话、表单          │ 引用与证据      │
│ 目录       │                           │ （可折叠）      │
└────────────┴───────────────────────────┴─────────────────┘
```

| 断点 | 行为 |
|-|-|
| ≥ 1280px | 三栏 |
| 960–1279px | 左栏收窄到 200px，右栏折叠为主区底部的引用列表 |
| < 960px | 单栏：步骤栏变顶部胶囊条（M5 再做） |

版心：正文单行不超过 **34 个汉字**（约 640px @15px）。超过就必须分栏或断段，这是"读物感"的硬指标。

## 6. 组件

### 6.1 步骤栏（借自"工具"方向）

左栏常驻，五项固定，编号用等宽：

```
01  情境
02  想法
03  检验     ← 当前：左侧 2px accent 竖线 + --tint 底 + 文字 --ink
04  行动
05  复盘
────
已用 6 轮
引用 1 处
```

- 已完成项：`--ink-2`，无勾选图标（不用 emoji，不用对勾图形，靠"当前项高亮"即可推断）。
- 当前项：竖线 + 淡底，**不做背景整条填充**，避免像导航菜单。
- 底部两行统计用等宽数字，是"工具感"的来源，也是用户判断"还要多久"的依据。

### 6.2 引用（脚注制）

这是整套规范里最重要的组件。

```
「肯定会搞砸」是一个预测，还不是事实。……结果分别是什么？¹

  │ 1　认知行为疗法指南 · 第 3 章 治疗实施 · 3.3 认知检验 · P.142
```

- 上标数字：`--accent`，11px，无链接下划线。
- 脚注块：左侧 2px `--accent` 竖线，缩进 11px，正文 11px `--ink-2`。
- 页码、章节号用等宽，便于扫读。
- 点击脚注 → 右栏展开该证据的完整卡片（来源机构、版本、审核状态）。
- **禁止**把引用做成"标签""胶囊""小卡片贴在句子后面"——那会让证据看起来像装饰。

### 6.3 消息（不做气泡）

CBT 对话不是聊天，不要用左右气泡加头像。

| 角色 | 呈现 |
|-|-|
| 用户 | 标签「你」11px `--ink-3` + 正文 `--ink-2` + 左侧 0.5px 竖线 |
| 引导（系统） | 标签「引导」+ 衬线 15px `--ink` |

理由：气泡把注意力引向"谁说的"，本产品要引向"说了什么、依据是什么"。

### 6.4 证据不足态（`EVIDENCE_INSUFFICIENT`）

**不是错误，不标红，不弹窗。**

```
我查到的资料不足以回答这一点。
已找到的相关内容：……（1 条，可能不直接相关）
建议：换一种问法，或参考 [来源名称] 原文。
```

用中性底色 + 正常字号，绝不用感叹号与警告三角。这个状态出现的频率会很高，视觉上必须"体面"，否则用户会以为系统坏了。

### 6.5 安全转介态（`SAFETY_HOLD`）

全宽卡片，`--refer` 只在这里出现：

```
这超出我能提供的帮助范围。
如果你现在有伤害自己的想法，请联系：
  · 你所在地区的心理援助热线
  · 就近精神科门诊 / 急诊
对话已暂停。我们不做判断，也不追问。
```

- 输入框禁用并说明原因，不给"继续"按钮。
- 不给风险等级、不追问细节（ADR-0004）。
- 卡片不做红色渐变、不闪动。

### 6.6 输入区

底部固定于内容区（非 `position: fixed` 于视口），上传线分隔。占位文案要具体：「说说最近一次让你有这种感觉的事」，而不是「请输入」。

### 6.7 记录页

表格化时间线，供导出 PDF：

| 时间 | 阶段 | 内容 | 用户确认 |
|-|-|-|-|
| 11-17 20:14 | 检验 | 三次汇报结果：两次正常 | — |
| 11-17 20:22 | 行动 | 汇报前写 3 条预测 | 已确认 |

时间戳等宽；「用户确认」列必须存在——它是这份记录能被机构采信的关键（`userConfirmedThought` 的界面体现）。

## 7. 语气（文案即界面）

| 场景 | 写法 |
|-|-|
| 引导提问 | 一次只问一件事；用"要不要""我们可以"，不用"你应该" |
| 说不懂 | "我查到的资料不足以回答" —— 主动、完整、不道歉三次 |
| 转介 | 陈述能力边界 + 给可执行路径，不煽情 |
| 按钮 | 动词短语：「继续」「看看别的解释」，不用「确定」「提交」 |

全套文案不使用感叹号。不用"加油""抱抱""你很棒"这类安慰性套话——它们会让专业定位滑向陪伴玩具。

## 8. 禁止项清单

- 渐变、玻璃拟态、阴影、发光
- emoji 作为图标或按钮
- 淡蓝 / 淡紫作为主色（"心理 App"刻板色）
- 左右气泡 + 头像的聊天布局
- 把引用做成胶囊标签
- 用红黄绿表示"严重程度"——本产品不做分级
- 字号小于 11px
- 字重 600 / 700
- 加载态用"思考中…"这类拟人化文案；用状态栏的骨架或"检索中 2/3"
