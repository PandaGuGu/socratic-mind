# 外部依赖与付费资源使用约定

本文件约束所有参与本项目的人与自动化代理（Agent）：**什么可以在没有额外许可的情况下调用，什么必须先获得授权。**

## 0. 这条规范为什么存在

2026-11-17，一次真实事件：助手在未事先取得授权的情况下，读取本机 `C:\API_KEY\Deepseek` 目录中的
密钥，用 DeepSeek 接口做了约 6 次对话调用以验证 `http` 档。花费不足 0.01 元，余额从 16.33 变为 16.33，
但它仍然是一次**没有授权的计费调用**。

当时助手在动手前发过一句"我先看它能不能用"。**那不是授权，只是报备。** 本规范要消除的正是这个模糊地带。

## 1. 三条硬规则

### 规则一：不主动调用任何计费接口

模型 API、云服务、付费数据源、短信/邮件通道，都算。默认状态是"不调用"，不是"试一下"。

### 规则二：报备 ≠ 授权

必须**事前**得到明确同意，且说明三件事：

| 要说明 | 举例 |
|-|-|
| 用途 | "验证 http 档能否正常返回带引用的回答" |
| 预计调用量 | "不超过 10 次对话请求" |
| 成本上限 | "预计 0.05 元以内" |

同意之后按这个范围执行；**超出范围要重新征求同意**，不能"顺手多试几个"。

### 规则三：凭证只经环境变量

| 允许 | 禁止 |
|-|-|
| 使用者在自己的终端 `export` 后启动服务 | 写入任何仓库内文件 |
| 通过 CI 的 Secret 注入 | 打印到日志、写进报错信息 |
| 临时环境变量（进程结束即失效） | 出现在截图、文档、Issue、提交信息里 |

## 2. 分级

| 行为 | 判定 |
|-|-|
| 读仓库内文件、跑单元测试、本地构建 | **允许**，无需报备 |
| 调用本地已启动的服务（localhost） | **允许** |
| 下载开源依赖（Maven Central、npm） | **允许**；但要确认不是付费镜像 |
| 调用模型 API / 云服务 / 付费接口 | **需授权**，按规则二 |
| 读取使用者机器上的密钥、凭证目录 | **需授权**，且必须说明为什么要用 |
| 把密钥写进文件、提交、日志 | **禁止** |
| 私自扩大使用范围（换模型、加并发、跑全量） | **禁止** |
| 以"免费额度"为由跳过授权 | **禁止**——免费额度也是额度 |

## 3. 违反之后

不是"下次注意"，而是四步：

1. **立即停止**所有相关调用（进程杀掉，不只是"不再调用"）；
2. **报告实际用量**：调用次数、余额变化、覆盖范围；
3. **提供回滚**：受影响的代码、文档、提交，给出保留/回退的选项；
4. **留档**：在 [版本记录](../06-评估/01-版本记录.md) 或相关 ADR 中写明发生了什么，不留"看起来一切正常"的记录。

## 4. 执行手段

约定要靠检查，不靠记性。

| 手段 | 做什么 |
|-|-|
| `scripts/check-secrets.py` | 扫描工作区与暂存文件，发现疑似密钥立即报警（只报位置与规则名，不回显内容） |
| 提交前跑一次 | `python scripts/check-secrets.py` |
| Code Review 清单 | 新增配置文件时确认：无明文密钥、无真实端点、无个人 token |
| 新档位上线 | `http` / `pg` 这类需要外部资源的档位，README 必须写明"由使用者自行配置并启动" |

## 5. 与本项目其它文档的关系

- 开发期发生过一次未经授权的真实模型联调（详见 git 历史中的开发日志），此后默认档固定为 `stub`，
  任何真实端点都必须由使用者显式配置并自备凭证；
- [ADR-0002](../04-adr/ADR-0002-Java栈与Graph选型.md) 的 `http` 适配器属于"能力"，不等于"默认行为"：
  默认档仍是 `stub`，不需要任何凭证。
