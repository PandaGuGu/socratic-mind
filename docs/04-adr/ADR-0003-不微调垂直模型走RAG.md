# ADR-0003：不微调心理垂直模型，走通用模型 + RAG

- **状态**：已接受
- **日期**：2026-11-17
- **相关**：[方案对比 §2](../01-概览/03-方案对比.md)、[方案对比 §8](../01-概览/03-方案对比.md)、[流程与状态](../02-架构/02-流程与状态.md)

## 背景

开源中文心理模型（SoulChat、EmoLLM、MindChat 等）在共情与话术上明显更强。是否以其为主模型？

## 决策

第一版**不使用垂域微调模型作为主模型**，采用通用大模型（能力不低于 DeepSeek 同级）+ RAG + 结构化流程。共情短板靠提示词与风格示例约束，并单列为评估项。

## 备选方案与被否原因

| 方案 | 为什么没选 |
|-|-|
| SoulChat / EmoLLM 作主模型 | 微调换来的是**风格**而非**可靠性**（ESC-Eval 显示其在流畅度与建议有效性上并不占优）；7B 级在长文档理解与专业术语上偏弱 |
| 微调模型 + RAG 混合 | 指南更新要重训，而 `kb_evidence` 只需重新入库并切换版本；两套知识来源会造成归因困难 |
| 自建领域模型 | 无算力预算与标注能力，且解决不了出处问题 |

## 后果

**好处：** 知识更新=入库，不是重训；模型可随时替换（Spring AI `ChatModel` 抽象，按节点路由）；出处可审计。

**代价：** 共情表现弱于垂直模型与商业产品；对提示词质量依赖更高；需要额外的"风格示例"维护。

**复查触发条件：** 若评估显示"情感回应"维度显著拖累完成率（例如完成一轮 CBT 的流失集中在情绪表达后的第二轮），则考虑引入垂域模型**作为表达层**（只负责话术改写，不参与证据与状态判断），而不是替换主模型。
