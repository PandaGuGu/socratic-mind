# ADR-0009：账号是叠加层，会话归属仍以设备为准

- **状态**：已接受
- **日期**：2026-11-24
- **相关**：[ADR-0007](ADR-0007-会话归属与内部接口鉴权.md)、[CBT 状态机](../03-设计/01-CBT状态机.md)、[API 契约](../02-架构/05-接口契约.md)

## 背景

ADR-0007 把身份定成"设备级匿名令牌"，并明确接受"换设备或清缓存即失去旧记录"。v0.4.0 的[需求对齐](../06-评估/04-需求对齐.md)把这一条列为最大的已知缺口，同时留下一个必须先回答的产品问题：

> 历史记录随账号走，还是随设备走？

只有两个看似干净的选项：

1. **随账号走**：登录后把会话的归属改成账号。问题在于退出登录后，本机的匿名记录会从界面上消失——它们没有被删除，只是再也没人看得见。
2. **随设备走**：账号只是登录凭据，不涉及历史。问题在于"换设备能看到"这件事根本不成立，账号就白做了。

而且项目有一条贯穿始终的性质：**不注册也能完整使用，心理记录默认拿不走**。任何把账号变成前置条件的方案都会破坏它。

## 决策

**账号与会话是两个归属维度，同时成立。**

1. **`cbt_session.user_id` 不变**：它永远记录"这一轮是哪台设备开的"。登录不会改写它，退出也不会。
2. **新增可空列 `cbt_session.account_id`**：登录时把该设备上**尚未认领**的会话挂到账号下；登录状态下新开的会话在创建时就带上它。
3. **可见性二选一，不叠加**：设备令牌（未登录）只看 `user_id = 自己` 的；账号令牌**只看 `account_id = 自己账号`** 的。
   账号令牌里虽然签了设备 id，但不走设备归属这条捷径——否则同一个浏览器换个账号登录，就能读到前一个账号在这台设备上开的会话。
   登录时已把本机未认领的会话认领掉，所以"账号看不到自己设备的会话"在实践中不出现。其余一律 404，不区分"不存在"与"不是你的"。
4. **令牌分两版**：`v1` 只签设备 id；`v2` 把设备 id 与账号 id 一起签。把设备 id 装进账号令牌，是为了让"登录后新开的会话"仍属于这台设备——登录与退出因此都是可逆的。
5. **认领只认 `account_id IS NULL` 的会话**；v0.7.0 起还要用户显式确认（见文末"后续变更"）。同一台设备换人登录，后来者不会接手前一个人的记录。
6. **不把手机号、真名、生日作为身份字段收集**；邮箱只是登录名。口令用 PBKDF2-HmacSHA256（120k 次迭代，随机盐），邮箱唯一性靠数据库唯一索引。

## 备选方案与被否原因

| 方案 | 为什么没选 |
|-|-|
| 登录后把 `user_id` 改写为账号 | 退出登录后本机记录"消失"；而且迁移是不可逆的，一旦账号注销，会话就悬空 |
| 必须登录才能用 | 把一道注册墙放在一个求助场景的最前面，与"匿名优先"的产品性质直接冲突 |
| 只做设备令牌，不做账号 | 换设备即失去记录，这是 v0.4.0 里最实际的缺口，也是这一版要解决的问题 |
| 账号密码之外再加手机号/微信登录 | 多一个第三方就多一份可关联身份的数据；当前没有业务需要 |
| 把账号与会话合表（`cbt_session.account_id` 取代 `user_id`） | 丢失"哪台设备开的"这一事实，后台复核与问题定位都会变模糊 |

## 后果

- **换设备可用了**：在第二台设备登录，能看到已认领的会话，也能把第二台设备上的匿名会话认领进来；
- **退出登录可逆**：账号页把登录前的设备令牌单独存一份，退出时换回来，本机记录仍在；
- **共享设备有一个已知窗口**：如果两个人先后在同一台设备上注册，后来者会认领前者**尚未认领**的会话。系统没有设备指纹，无法区分"同一个人换账号"与"换了一个人"。已经认领过的会话不会被第二个账号接手，也不会被第二个账号读到；文案里明说了这件事，真正的解法是指纹或二次确认，属于后续决策；
- **没有找回口令**：没有发信通道，忘记口令即失去账号。这是 v0.5.0 最大的功能缺口；v0.7.0 用"注册时抄下的一次性恢复码"补上，但仍没有邮件找回；
- **没有邮箱验证**：邮箱不证明归属，只作为唯一登录名；
- **令牌本身仍是无状态的**：退出即丢弃；v0.6.0 起注销账号会让全部账号令牌立即失效（见下节），但没有独立的吊销列表，也没有"只踢掉某一台设备"；
- **退出登录后范围变小**：只能看到这台设备开的会话，账号名下来自其他设备的记录暂时不可见——这正是"退出"应当表达的意思；
- **浏览器是这台设备的信任边界**：同一浏览器里换账号看不到前一个账号的会话，但同一个人清掉 localStorage 就能拿到设备令牌。要实现"同一浏览器多用户隔离"，得把设备身份也换成登录态，那会破坏匿名优先；
- **后台开始区分账号**：v0.6.0 起有只读的 `/internal/accounts.html`；它不提供代客注销。

## 后续变更（v0.6.0）

这一版补了两件与"账号作为叠加层"直接相关的事，不改变上面的决策，只把两个后果收掉：

1. **注销**：`POST /api/auth/delete` 要口令确认。注销时先 `releaseAccount` 把 `account_id` 清空，再删 `app_account`。
   会话不删——第一归属是设备，账号只是第二把钥匙；注销等于把钥匙还回去。回跳账号页会说明"这 N 轮回到本机设备名下"。
2. **注销即吊销**：产品接口在验签之后多查一次"账号还在不在"（`CbtController.identity`）。
   账号被删，同一枚 `v2` 令牌立刻 401。这样不需要令牌表，也不需要过期策略，代价是每请求一次账号查询；
   规模上来后应当换成短 TTL 缓存，而不是退回不查。

v0.6.0 时仍然没有：找回口令、邮箱验证、改口令、第三方登录。v0.7.0 已补恢复码、改口令、退出其他设备；仍无邮箱验证与第三方登录——缺的是发信通道。

## 后续变更（v0.7.0）

这一版改了两个与"账号是叠加层"直接相关的行为：

1. **认领从"自动"改成"用户确认"**。登录/注册只返回 `pendingClaims`，页面问一句"这台设备上还有 N 轮，
   要归到这个账号吗？"，用户点确认才调 `/claim`。原来"同一台设备后来者接手前者未认领会话"的窗口，
   靠这一道确认关掉——系统不再替用户判断"换账号"还是"换了人"。
   代价是多一步点击；收益是匿名记录不会在登录时被悄悄改变归属。
2. **令牌可失效**：账号增加 `token_epoch`，账号令牌里签着它。
   改口令、退出其他设备、用恢复码重置口令都会 +1，旧令牌里的 epoch 与账号当前值不符，产品接口立即 401。
   这比维护令牌表便宜，也比"只能等密钥轮换"诚实；代价是每个请求多一次账号查询。

同版补了恢复码（注册时一次、用一次即作废）与改口令，但没有邮箱验证：
没有 SMTP 通道，邮箱仍然只是登录名，不是"能收信"的证明。

**2026-11-27 补充（紧急联系人）：** 账号增加可选的紧急联系人（称呼 / 电话 / 关系），
只用于安全暂停时的危机卡片；它不是身份字段——不参与登录、不做验证、不用于任何推断，
用户可随时清空，注销账号时一并删除。原文"不收集手机号"指的是不作为身份信息收集，
这条边界没有变。
