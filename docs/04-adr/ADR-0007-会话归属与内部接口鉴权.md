# ADR-0007：会话归属用匿名令牌，内部接口必须持钥

- **状态**：已接受
- **日期**：2026-11-19
- **相关**：[流程与状态](../02-架构/02-流程与状态.md)、[接口契约](../02-架构/05-接口契约.md)、[内部后台](../03-设计/03-内部后台.md)

## 背景

v0.1.0 跑通链路时，两条假设被写进了代码而不是文档：

1. 会话 id 由自增序号生成，接口没有身份校验——`GET /api/cbt/sessions` 不传 `userId` 会列出全库；
2. 内部接口默认开启且无鉴权——`PUT /api/internal/policy` 可以把输出策略的禁句删空，`PUT /api/internal/flow` 可以改掉确认节点的去向。

这两条在演示环境里"方便"，在真实环境里意味着：按序枚举即可读到任何人的情境、自动想法与确认内容；任何人可以关掉输出闸门。心理记录属于敏感个人信息，这不是"以后再说"的项。

## 决策

**1. 用户侧：匿名令牌，不做账号。**
- 服务端在设备第一次开口时生成随机 `userId`，用 HMAC-SHA256 签发 `v1.<payload>.<sig>`；
- 客户端只持有令牌（localStorage），所有会话操作必须携带 `X-User-Token`；
- 会话归属以令牌里的 `userId` 为准，客户端传来的 `userId` 一律忽略；
- 不属于当前身份的会话返回 **404**（不是 403），避免把"这个 id 存在"变成可探测信息。

**2. 内部侧：默认关闭 + 必须持钥。**
- `psych.internal.enabled` 默认 `false`；打开时若未配置 `psych.internal.token`，**启动失败**；
- `/api/internal/**` 与知识库写入接口统一校验 `X-Internal-Token`（常量时间比较）；
- 知识库入库不再接受 `publish=true` 直通发布，`publish` 只表示"提交审核"，`/review` 的 approve 才能成为可引用证据。

## 备选方案与被否原因

| 方案 | 为什么没选 |
|-|-|
| 做完整账号体系（手机号/微信） | v0.1 没有业务需要收集手机号；收集即产生合规义务与泄露面。将来接账号时，令牌机制可以保留为"未登录设备"的降级路径 |
| 用 Cookie Session | 会话 Cookie 不解决"匿名设备"的归属问题，还引入 CSRF；Bearer 式令牌对同源前端更简单 |
| 把会话 id 换成 UUID 就够了 | 只提高枚举成本，不解决"知道 id 就能读"；归属判断必须由服务端签名保证 |
| 内部接口靠"只监听 127.0.0.1" | 部署形态（容器、反代）不保证这一点；而且本机上的其他进程同样能访问 |

## 后果

- 用户换设备/清缓存后无法访问旧记录（没有账号可迁移）——这是 v0.1 明确接受的代价，导出/迁移等做账号时再解决；
- `psych.security.secret` 未配置时启动生成临时密钥，重启后旧令牌失效：本地开发可接受，生产必须通过 `PSYCH_USER_SECRET` 固定；
- 内部后台第一次访问会提示输入令牌，开发档默认 `dev-internal-token`（仅 localhost 使用）；
- 旧数据（`userId=anonymous` 或前端自造的 `u-xxxx`）在新版本中不再可访问，属于一次性迁移成本。
