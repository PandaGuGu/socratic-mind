# 第 8 章 接口设计

## 8.1 第一版接口清单

第一版不需要复杂 API。先设计这些接口：

| 接口 | 方法 | 作用 |
|-|-|-|
| `/api/knowledge/chat` | POST | 心理知识问答 |
| `/api/knowledge/documents` | POST | 上传知识资料 |
| `/api/knowledge/documents` | GET | 文档列表（内部令牌） |
| `/api/knowledge/documents/{id}/chunks` | GET | 切分预览，含父块（内部令牌） |
| `/api/knowledge/documents/{id}/review` | POST | 审核文档 |
| `/api/knowledge/search` | POST | 测试知识检索 |
| `/api/knowledge/stats` | GET | 知识库统计（内部令牌） |
| `/api/cbt/sessions` | POST | 创建 CBT 会话 |
| `/api/cbt/sessions/{id}/messages` | POST | 发送消息并恢复 Graph |
| `/api/cbt/sessions/{id}` | GET | 获取会话状态 |
| `/api/cbt/sessions/{id}/history` | GET | 获取会话历史 |
| `/api/cbt/sessions/{id}/end` | POST | 结束会话 |

## 8.2 CBT 消息接口契约

请求：

```json
{
  "sessionId": "session_001",
  "message": "最近我总是因为学习任务感到焦虑",
  "clientMessageId": "msg_001"
}
```

响应：

```json
{
  "sessionId": "session_001",
  "stage": "problem_identification",
  "status": "awaiting_user",
  "response": "最近一次让你产生这种感受的具体事情是什么？",
  "citations": []
}
```

字段语义：

| 字段 | 说明 |
|-|-|
| stage | 当前节点名，取值必须来自 [§5.3](05-双Graph设计.md) 的节点清单 |
| status | `awaiting_user` / `running` / `ended` / `safety_hold` |
| response | 本轮面向用户的话术；流式时逐段推送 |
| citations | 本轮回复用到的引用；CBT 通常为空，干预决策节点可能有 |
| clientMessageId | 幂等键，重试不重复推进 Graph |

## 8.3 流式响应

建议使用 **SSE** 实现流式响应，但 **Graph 的内部状态更新必须由后端控制，不能让前端直接修改任意 State 字段**。

三种事件的边界：

| 事件 | 内容 | 谁来改状态 |
|-|-|-|
| `token` | 文本增量 | 不改状态 |
| `state` | 阶段、status、待确认项 | 后端节点写入，前端只读 |
| `done` | 本轮结束 + citations | 后端落库后发出 |

## 8.4 接口设计的三条硬约束

1. **前端不能写 State。** 只有"发消息"一个入口能推进 Graph。
2. **`stage` 必须是枚举，不是自由字符串。** 否则前端会按字符串匹配做分支，加节点即崩。
3. **知识问答与 CBT 的接口不共用 Session。** 两者的会话表、threadId 命名空间、权限检查都分开，避免知识问答的历史被当成 CBT 记录（[ADR-0005](../03-adr/ADR-0005-双Graph独立State.md)）。

接口的细化契约（字段校验、错误码、分页）见 [docs/02-设计/API契约.md](../02-设计/API契约.md)，M2 定稿。
