# 第 11 章 评估指标

## 11.1 为什么必须量化

心理领域不能只用"回答看起来不错"来验收。第一版必须有的评估分成三组。

| 评估维度 | 指标 |
|-|-|
| RAG 检索质量 | Recall@K、MRR、引用命中率 |
| 回答质量 | 忠实度、引用支持率、无依据陈述率 |
| CBT 流程质量 | 节点路由正确率、状态恢复成功率、用户确认状态正确率、安全分流测试通过率 |

三条容易被忽略的口径：

- **引用支持率**要人判："这段引用是否直接支持这句结论"，不是"引用是否相关"。
- **状态恢复成功率**要覆盖异常路径：重复提交、客户端断开、恢复时版本已变。
- **安全分流**必须同时报召回率和误报率（见 [§2.8](02-相关方案横向对比.md)），只报召回等于鼓励过度拦截。

## 11.2 三类测试集

1. **知识测试集**：由权威资料整理问题及标准出处。
2. **CBT 流程测试集**：同一个案例覆盖不同回答、拒绝回答、修改回答和中断恢复。
3. **安全测试集**：模糊表达、明确危险信号、误报场景和提示词注入。

测试集的建立与扩充规则见 [docs/05-评估/测试集说明.md](../05-评估/测试集说明.md)。

## 11.3 评估怎么组织

评估最好由**规则测试、独立模型辅助评估和专业人员审核**共同完成。

> 模型之间意见一致，不等于临床正确。

分工建议：

| 环节 | 谁做 | 产出 |
|-|-|-|
| 检索指标（Recall / MRR） | 脚本自动 | 每次提交跑，出趋势 |
| 引用支持率、无依据陈述率 | 独立模型初筛 + 人工抽检 | 按版本留档 |
| CBT 流程与状态恢复 | 自动化用例 | 通过/失败清单 |
| 安全分流 | 安全测试集 + 专业人员复核 | 召回/误报双指标 |
| 临床表述边界 | 专业人员 | 抽检意见，进下一版 |

## 11.4 与第 2 章三组对照的关系

第一版验收不只要"跑通了"，还要回答"自研的增量有多大"。三组对照实验（A 通用模型直答 / B 通用 RAG / C 本方案）的组别定义、专用指标与预期方向见 [§2.8](02-相关方案横向对比.md)，建议并入 M6 一起跑。

这三组数据同时是 [§2.3.1](02-相关方案横向对比.md) 中"是否继续自研"这一延迟决策的判据。
