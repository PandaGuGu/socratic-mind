# 第 9 章 技术选型与依赖

## 9.1 第一版依赖清单

| 技术 | 用途 | 优先级 |
|-|-|-|
| Spring Boot | 后端框架 | P0 |
| Spring AI | ChatModel、Embedding、VectorStore | P0 |
| Spring AI Alibaba Graph | 工作流引擎 | P0 |
| PostgreSQL | 业务数据 | P0 |
| pgvector | 向量检索 | P0 |
| PostgreSQL FTS | 关键词检索 | P0 |
| Redis | 缓存、限流（可后加） | P1 |
| MinIO / 对象存储 | 原始文档存储 | P1 |
| Reranker | 检索结果重排 | P1 |
| Elasticsearch | 扩展全文检索 | P2 |
| Neo4j | 知识图谱 | P2 |

P0 是 M1–M2 的最小闭环，P1 在 M3–M4 按需引入，P2 不属于第一版范围。

## 9.2 版本兼容：这是本项目最容易踩的坑

> **Spring AI 和 Spring AI Alibaba 的版本兼容关系一定要先确定。**

官方文档目前展示的 Spring AI RAG API 和 Graph API 可能对应不同发布节奏，**不能简单地将各自最新依赖版本混合**。先以 Spring AI Alibaba 的版本说明和对应示例工程为准。

落地检查顺序（M1 第一天就要做完）：

1. 从 Spring AI Alibaba 官方仓库的版本说明确定 Graph 版本；
2. 在它的示例工程里读 `pom.xml`，抄其中的 Spring AI / Spring Boot 版本，而不是自己组合；
3. 跑通"调模型 + 建 Graph + 存读状态"三件事后再往里加业务；
4. 把最终确定的三个版本号记进 `backend/pom.xml` 的 `<properties>`，并在此处回填。

### 9.2.1 当前实际锁定的版本（2026-11-17）

| 组件 | 版本 / 取值 | 说明 |
|-|-|-|
| JDK | Temurin 21.0.12 | `<maven.compiler.release>21` |
| Spring Boot | 3.5.6 | 父 POM |
| Spring AI / Spring AI Alibaba | **未引入** | M1–M2 用端口隔离，理由见 [ADR-0002 备注](../03-adr/ADR-0002-Java栈与Graph选型.md) |
| 存储 | 内存实现（默认）/ PostgreSQL 16 + pgvector（未验证） | `psych.store` |
| 模型 | 桩实现（默认）/ OpenAI 兼容 HTTP（未验证） | `psych.ai.provider` |

也就是说：**"版本兼容"这个最大风险目前只是被绕开了，没有被解决。** 真正解决它要等到接入
Spring AI 的那一天，届时仍需按 §9.2 的顺序核对，不能因为"已经能跑"就跳过。

## 9.3 需要单独核实的点

| 事项 | 为什么容易出事 | 何时确认 |
|-|-|-|
| Checkpointer 的存储后端 | 不是每个版本都对 PostgreSQL 提供官方 Saver | M1 |
| `VectorStore` 与 pgvector 的索引类型 | HNSW / IVFFlat 的参数影响召回与延迟 | M2 |
| RRF 融合的实现位置 | 框架可能有，但元数据过滤需要自己加 | M2 |
| 模型按节点路由 | 需要一个能配"节点 → 模型"的抽象层 | M3 |
