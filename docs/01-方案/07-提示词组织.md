# 第 7 章 提示词组织

## 7.1 不要写在 Java 类里

不要把所有提示词写在 Java 类里。建议采用独立 Markdown 文件，方便版本管理和修改。

```
resources/
└── prompts/
    ├── common/
    │   ├── system-role.md
    │   ├── safety-rules.md
    │   └── output-rules.md
    │
    ├── knowledge/
    │   ├── classify-query.md
    │   ├── rewrite-query.md
    │   ├── evaluate-evidence.md
    │   ├── generate-answer.md
    │   └── verify-citation.md
    │
    └── cbt/
        ├── safety-check.md
        ├── problem-identification.md
        ├── cognitive-extraction.md
        ├── cognitive-review.md
        ├── intervention-decision.md
        ├── action-design.md
        ├── result-review.md
        └── session-summary.md
```

## 7.2 每个 Prompt 带元数据

建议给每个 Prompt 增加版本号和适用节点：

```yaml
prompt_id: cbt_cognitive_review
version: 1.0.0
language: zh-CN
node: cognitive_review
output_format: json
```

这样以后修改提示词，可以追踪不同版本是否影响 Agent 行为。

字段约束：

| 字段 | 必填 | 说明 |
|-|-|-|
| prompt_id | 是 | 全局唯一，推荐 `{graph}_{node}` |
| version | 是 | 语义化版本；指令语义变化升 minor，仅措辞升 patch |
| language | 是 | 第一版全部 zh-CN |
| node | 是 | 必须与 [§5.2](05-双Graph设计.md) 节点表一致 |
| output_format | 是 | `text` / `json`；json 时必须给出 schema 或示例 |

## 7.3 组织原则

1. **一个节点一个文件**，不要一个文件塞多节点；否则改一处等于全量回归。
2. **common 层只放跨节点共用的规则**（角色、安全、输出格式），节点文件只写该节点特有指令。重复的规则会造成"改了一处忘了另一处"。
3. **安全规则优先级高于一切节点指令**，且在 `common/safety-rules.md` 里集中维护，不在各节点重写。
4. **prompt 变更必须能被评估**：改 prompt 就走 [第 11 章](11-评估指标.md) 的测试集，结果留档。
5. 提示词里不写具体模型名与参数，模型按节点路由配置（[§2.2.1](02-相关方案横向对比.md)）。

规范细节见 [提示词规范](../04-规范/提示词规范.md)。
