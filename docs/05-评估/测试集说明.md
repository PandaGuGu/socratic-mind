# 测试集说明

配套 [第 11 章 评估指标](../01-方案/11-评估指标.md)。第一版的三类测试集放在 `eval/datasets/`，一条用例一个 JSON 行，便于 diff 与统计。

## 1. 三类测试集

### 1.1 知识测试集（`eval/datasets/knowledge/`）

由权威资料整理问题及标准出处。

```json
{
  "id": "k_0001",
  "question": "……",
  "expected_source": {"document": "……", "page": 42, "section": "3.2"},
  "answer_must_contain": ["……"],
  "answer_must_not_contain": ["……"],
  "difficulty": "easy | medium | hard",
  "note": "为什么收这条"
}
```

建集规则：
- 每条必须有**可核对的页码或章节**，否则无法算引用命中率；
- 至少 20% 是"资料里没有答案"的题，用于验证拒答能力；
- 至少 10% 是"两份资料说法不一致"的题，用于验证冲突分支。

### 1.2 CBT 流程测试集（`eval/datasets/cbt/`）

同一个案例，覆盖四条路径：

| 路径 | 覆盖点 |
|-|-|
| 正常回答 | 五步走完，状态字段逐步填充 |
| 拒绝回答 | 用户不提供情境时，系统不硬推流程 |
| 修改回答 | 用户回头改自动思维，验证 `userConfirmedThought` 与候选分离 |
| 中断恢复 | 会话中断后从 threadId 恢复，阶段不倒退 |

### 1.3 安全测试集（`eval/datasets/safety/`）

样本类型：模糊表达、明确危险信号、误报场景（如引用新闻、学术讨论）、提示词注入。

标注要求：每条给 `expected_action`（`normal` / `referral`）与 `rationale`。**必须包含误报场景**，否则只会训出一个到处转介的系统。

## 2. 扩充与版本

- 测试集随 git 版本化；新增用例只追加，不改已有 `id` 的语义。
- 每条用例保留 `note`，说明收它的动机；没有动机的用例三个月后没人敢删。
- 每次跑分结果写 `eval/results/YYYYMMDD-<commit>-<suite>.json`，不入库（已在 `.gitignore`）。

## 3. 判分

| 指标 | 判分方式 |
|-|-|
| Recall@K / MRR | 脚本自动，比对 `expected_source` |
| 引用支持率 | 独立模型初筛 + 人工抽检（抽检比例不低于 20%） |
| 无依据陈述率 | 同上 |
| 安全分流 | 混淆矩阵，同时报召回与误报 |
| 状态恢复 | 自动化断言 `stage` 与关键字段 |

专业人员审核的意见单独记在 `eval/results/reviews/`，不混入自动分数。
