# 需求对齐

对象是一份课程作业的功能清单（10 条）。本文逐条说明**在哪实现、怎么证明、边界在哪**，
不写"已完成"三个字了事——能演示、能跑测试、能指出文件，才算对齐。

对应版本 v0.5.0。测试 155 项通过（`mvn -o test`）。

## 逐条对照

| # | 需求 | 实现 | 证据 | 边界 |
|-|-|-|-|-|
| 1 | 匿名文字倾诉 | HMAC 令牌签发身份，**不登录即可用**；`X-User-Token` 之外不接受任何身份声明。v0.5.0 起可自愿注册账号把记录带走；v0.6.0 起可注销，注销即吊销该账号的全部令牌 | `UserTokenService`、`SessionAuthTest`（无令牌 401 / 伪造 401 / 他人 404）、`AccountAuthTest`（含注销后 401） | 不注册时令牌是设备级，换设备即失去旧记录；注销后本机记录仍在，但账号与登录方式消失 |
| 2 | 语音倾诉 | Chrome/Edge 用 Web Speech API 在浏览器内转文字；Firefox 等没有 Web Speech 的浏览器录音后发到**本机**转写接口（`/api/asr/transcribe`），结果落进输入框再发送 | `room/index.html` 的 `toggleVoice()`、`AsrController`、`scripts/asr_transcribe.ps1` | Chrome/Edge 不录音不上传；Firefox 的音频只到本机转写进程，不落库；需要系统语音包（本机 zh-CN 已验证），换 Vosk/Whisper 只改一条命令 |
| 3 | AI 以 CBT 框架引导识别认知偏差 | 五阶段流程由代码推进；`DistortionTagger` 从自动思维标出 9 类候选偏差，检验阶段回显提示 | `DistortionTagger`、`DistortionTaggerTest`（3 项） | 只给候选，不写诊断、不写进总结、最多 3 个 |
| 4 | 危机干预预警 | `SafetyScreener` 六级规则 + 自评 ≤3 进"关注"；命中即暂停并转介 | `SafetyScreenerTest`、`CrisisCardTest` | 关键词规则来自工程常识，未经临床审核 |
| 5 | 匿名机制 | 同上；`userId` 由服务端从令牌还原，前端传入的 `userId` 一律忽略。账号是可选叠加层：会话归属仍是设备，账号只扩大可见范围（ADR-0009）。v0.7.0 起登录不自动认领、要用户确认；改口令/退出其他设备/重置口令会让旧令牌立即失效 | `CbtController.start()` 与 `canSee()`、`app_account` 表、`AuthService` | 没有邮箱验证（没有 SMTP）；恢复靠注册时抄下的一次性恢复码 |
| 6 | 敏感词过滤 | `SensitiveLexicon`：NFKC/零宽/全角/重复字归一化 + 三级动作（block/mask/review），输入输出两侧分 scope。v0.6.0 起可在 `/internal/lexicon.html` 整表编辑，保存即生效 | `lexicon/sensitive.txt`、`SensitiveLexiconTest`（6 项）、`LexiconAdminTest`（4 项：加词下一句就拦、删空 block / 关掉输入侧 / 只剩三条 / 重复词条均被拒、回滚生成新版本） | 不做拼音、拆字、谐音对抗；门槛是结构门槛（至少 10 条、一条 block、一条 in/both），不是内容审核；宁窄勿宽 |
| 7 | 紧急联系人触发 | 会话级联系人（称呼/号码/关系）；安全暂停时生成危机卡片：热线 + 联系人 + 可复制的通知文案；后台可见并标记"已处理" | `CrisisCard`、`POST /api/cbt/sessions/{id}/contact`、`POST /internal/sessions/{id}/ack` | **不自动外呼、不发短信**：没有资质，误报责任由用户承担 |
| 8 | 心理咨询专用 System Prompt | `prompts/cbt/counselor.md` 作为共享前言，拼在改写想法、写总结两处 system 最前 | `CbtFlow.system()`；`PromptAssetTest` 锁结构 | 它不是"咨询师人格"，是禁止清单；流程仍由代码推进 |
| 9 | 情绪状态追踪 | 用户自评 0–10（只能点，不能推断）+ 情绪词标签（`EmotionTagger`）；序列落库，房间画折线；v0.6.0 起有跨会话按天聚合（`GET /api/cbt/mood/trend`），窗外画 30 天折线 | `MoodPoint`、`POST /{id}/mood`、`MoodController`、`SessionPagingTest` | 单一时间点低分不等于危机；跨会话只做"把点排在一起"，不插值、不预测、不下"变好了"的结论 |
| 10 | Safety Filter | 输出侧 `GuardedChatPort`：长度 / 禁句 / 敏感词 / 与输入重合度 → 带原因重写 → 模板兜底；策略三档可后台调 | `GuardRules`、`GuardedChatPortTest` | 误判代价是质量下降，漏判代价是越界话术 |

## 演示顺序（答辩用，约 3 分钟）

1. `/room/` 点小人 → 点麦克风说一句（Chrome），文字自己出现在输入框；
2. 点情绪刻度 `3` → 提示"要不要先停一下"，后台该会话变成**关注**；
3. 正常走完"情境 → 想法"，输入"我肯定会被开除，一切都完了" → 检验阶段出现**灾难化**提示；
4. 另开一轮，输入"加微信详聊" → 整句被拦，流程不推进；
5. 再说"我真的不想活了" → 暂停，卡片给出 12356 / 120，留联系人后可**复制一段发给对方的话**；
6. `/internal` 该会话显示**安全暂停**、联系人、自评分，点"标记已处理"落时间；
7. `/account/` 注册一个账号 → 回房间，窗外刚才那几轮都还在（已认领）；退出登录后本机记录仍在；
8. `/internal/lexicon.html` 加一条 block 词并保存 → 回房间发一句含这个词的话，整句被拦；再把 block 删光点保存，服务端拒绝；
9. `/internal/index.html` 选中一条会话 → 右上"记录页" → 打印/存 PDF，纸上包含过程、确认过的说法、情绪分与边界声明。

## 为什么有两件事"实现了但没有做满"

**语音不存音频。** 存音频等于给自己造一个高价值攻击面，而课程作业没有相应的加密、留存、删除链路。转文字后即弃，功能在、风险不在。要真存，得先有存储加密与生命周期策略。

**联系人只触发"人"，不触发"通道"。** 自动发短信/打电话需要资质与责任约定，误报一次就是真实伤害。所以系统做的是：把热线摆在最前、把联系人摆出来、把该说的话写好，**发送键留给用户**。这条比"接个短信 API"难解释，但它是唯一站得住的实现。

## 已知缺口

- **账号补到"能自救"**：v0.7.0 有一次性恢复码、改口令、退出其他设备、注销即吊销；仍没有邮箱验证（没有 SMTP）、第三方登录，也没有"只踢掉某一台"；
- **共享设备的认领窗口已关**：登录/注册只报告可认领数量，用户点确认才认领；不再自动接手前一个人的会话；
- **账号视图是只读的**：`/internal/accounts.html` 能看账号、会话数与"需关注"轮次，但没有代客注销——那需要本人口令；
- **临床审核仍是人的事**：v0.7.0 增加了审核记录（谁、何时、审的哪一版），改版后自动标"需重审"；但系统不能替临床医生签字，默认状态仍是"未审核"；
- 偏差词表是规则，召回有限，复杂句式会漏；
- 自评曲线：有跨会话按天聚合，但仍没有 program（把多轮组织成一个疗程）概念，所以没有"疗程内对比"；
- 词库可在线编辑、可回滚（v0.6.0/v0.7.0），门槛是结构门槛，不是内容审核；
- 语音：Chrome/Edge 走浏览器识别；Firefox 依赖本机转写服务（Windows 语音包已验证，Linux/容器默认没有）。
