## v0.2.0 发布

这一版没有新功能，做的是三件收尾的事：

- **版本号对齐**：`pom.xml` 从 0.1.0 提到 0.2.0，此前三版改动都只体现在文档里，jar 名还停在 0.1.0；
- **文档重排**：README 改成"先看图和结论"的写法；docs 入口改成按意图分流；三份验收文档合并成本页，原文移入 [归档](../99-归档/README.md)；
- **截图入库**：房间、控制台、规则与参数三张实际运行截图进 `docs/assets/current/`。

功能面与 v0.1.2 一致，因此测试数不变（102 项）。

## v0.1.0 链路跑通

证明"两个工作流 + 一个知识库"能跑完整一轮。

- 对话：房间页接真实 `/api/cbt/*`，五阶段 + 干预分支 + 中断确认；
- 知识：入库 → 切分 → 检索（向量 + 全文）→ 证据 → 引用校验，证据不足会拒答；
- 存储：`cbt_session` / `cbt_message` / `cbt_turn` 落库，H2 实测重启存活；
- 后台：会话轨迹、输出策略、流程画布三页，改完立即生效。

验收物：6 张界面截图 + 全链路走查，见 [归档原文](../99-归档/v0.1.0-全链路验收.md)。

## v0.1.1 安全加固

跑通之后先堵"能出事"的口子。

| 问题 | 修法 |
|-|-|
| 会话 id 自增、接口无鉴权，可枚举读别人记录 | HMAC 匿名令牌 + 归属校验；不属于本人一律 404；id 加随机后缀 |
| 列表接口不传 userId 返回全库 | 只按令牌身份返回 |
| 内部接口默认开、无鉴权，能改禁句与流程 | 默认关闭；开启必须配令牌，否则启动失败 |
| 知识库 `publish=true` 直通发布 | 入库一律待审核，`/review` 通过才可检索 |
| "他/她/朋友"一出现就放行，"我不想活了，他不知道"会漏判 | 本人意图 HOLD；他人/引用 → REVIEW 队列；补英文与"想消失"等表达 |
| 放行只写字符串，没人看得到 | 待复核队列 + 控制台徽章 |
| 求助信息不可执行 | 12356（全国统一心理援助热线）+ 120 |
| 并发覆盖、写无事务、幂等无界 | 分段锁 + 事务 + 有界幂等 + 限流与长度上限 |
| 「我再改改」是死路 | 编辑态走 `/confirm` 的 `thought` |
| 默认流程缺节点、成环时空白纸片 | 补全拓扑 + 环检测 + 空话术兜底 |

测试从 69 增至 85 项。过程与逐条验证见 [归档原文](../99-归档/v0.1.1-安全加固.md)。

## v0.1.2 后台可控

把"半夜想改、改错会出事"的三样东西交给运维，同时不让它们被改坏。

| 对象 | 可改 | 门禁 |
|-|-|-|
| 安全规则 | 新建/删除/改正则、级别、启停 | 用例回放；至少 1 条 hold 规则 |
| 发布用例 | 增删改文本与期望 | 下限 5 条 HOLD、2 条 PASS，不能删空 |
| 运行参数 | 消息长度、每分钟条数、每小时新会话 | 范围校验 |
| 系统话术 | 6 句非阶段话术 + 占位符 | 键与占位符白名单 |
| 历史版本 | 列表带时间与操作者，可看内容并与当前对比 | 回滚生成新版本，内容同样过门禁 |

"改窄"会被用例指出失效项，"删空用例"被下限拦住，"删掉唯一覆盖某句的规则"同样会被用例挡住——
不靠写死 id，靠行为基线。

测试增至 102 项。逐条验证见 [归档原文](../99-归档/v0.1.2-后台可控.md)。

## 仍未解决

按"会不会影响上线"排序：

1. **模型层是桩**：生成质量、延迟、成本未验证；`http` 档已接真实接口，但没有账单与效果数据。
2. **检索是哈希向量**：语义召回未被证明，无关查询会返回低分噪声命中。
3. **M6 评估未开始**：`eval/datasets` 为空，三组对照与指标都没有数据。
4. **PostgreSQL/pgvector 未实跑**：目前用 H2 的 PG 兼容模式验证会话域。
5. **认知检验只收反例**：`evidence_for` 仍是空字段，要采"支持证据"得改协议。
6. **令牌是设备级、不可迁移**：清缓存或换设备即失去旧记录（ADR-0007 明确接受）。
7. **限流是单机的**：多实例部署要挪到网关。
8. **安全规则未经临床审核**：可编辑提高了响应速度，没有改变"规则来自工程常识"这一事实。
