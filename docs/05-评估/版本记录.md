## v0.6.0 运营收口

这一版把"后台能改"推进到"后台能管"：运营不改代码就能换流程、换模型、查审核、导出记录。

### 流程画布：多库与起点

- 画布从单份配置变成库：新建、复制、改名、删除，各自有草稿与已发布两份；
- 存草稿不动线上，单独"启用"才切换运行时；启用前做结构校验（起点可达、阶段完整）；
- 右键任意阶段"设为起点"，起点必须能走到总结，校验不过的起不启用；
- 旧 `flow-params.json` 首次启动自动迁移成一张画布，历史版本移到 `config/history/flow*`。

### 审核：从规则扩到记录

- 审核对象扩到安全规则、敏感词库、流程、输出策略、限流与会话六类；
- 每条审核留版本、署名（取自登录身份而非输入框）、时间、清单勾选与备注；
- 改版自动回到待审；页面显示版本差异、待审徽标与未审核提醒；
- 记录可导出 JSON/CSV；新增"对话历史心理复核"：逐轮看用户表达，标记风险并上报。

### 模型：三档热切换

- 后台可填云端 API Key、切本地 Ollama、退回桩，保存即生效，不用重启；
- 提供连通性测试与本地模型启动/状态查询；Key 存在 `config/ai-config.json`（已忽略，不进库）。

### 用户侧：记录能带走

- 账号页可导出账号信息与自己的对话（JSON/Markdown），导出前可预览；
- 只导出本人的会话，限流 5 次/分钟，不带内部轨迹；
- 后台顶栏加圆形头像，进入个人设置（身份、改密、退出）。

### 证明

`mvn -o test` 202 项（v0.5.1 为 194）。本机 H2 档与容器档均实跑：多画布新建/复制/启用/删除、
起点迁移、审核六类署名、会话复核上报、模型切换与测试、导出与预览。

### 边界

- 会话复核仍是辅助提示，不替代临床判断，也不自动外呼；
- 云端模型的成本与延迟未做长期压测；本地模型仍只在 CPU 上跑过；
- 导出为同步生成，单次数据量大时会占用请求线程；
- 多画布只在单实例上验证，跨实例的并发编辑没有锁。

## v0.5.1 检索与治理

这一版没有新页面、没有新话术，做的是"让已经有的东西能被证明"。

### 检索：补上重排

四档可切（`none` / `lexical` / `fixture` / `http`），加 `pool-factor=3`：召回先放大、重排后再截断。
顺序反了（先截后排）等于没排，这是实现里最容易写错的一处。

排序分数来自两个子代理**独立扮演 cross-encoder** 的标注，按内容键（检索文本短 SHA）索引——
用 chunk id 做键的文件，重建语料第二天就静默失效。标注一致性：top-1 一致 1.0、top-3 重合 0.87、
逐条平均绝对差 0.045。5 个查询上改变了 4 个的 top-1。

边界：真 bge-reranker 未联调，`http` 档只有代码。

### 语料：生命周期与权限

- 同步按 `external_key` 去重、按 `content_hash` 决定是否重做；内容变了清旧块、写新版本、**回到待审**；
- 软删除立即退出检索，7 天后物理清理；
- ACL 在**检索前**过滤（不是生成后删引用）；组织模式下匿名调用只能看公开资料——
  这一条是补漏：原来 `null` 表示"不过滤"，设了 ACL 前台照样搜得到。

### 后台：组织域与真登录

- 租户/团队/成员落库；两把钥匙：系统令牌证明来源，操作者令牌证明身份；
- 口令登录 → HttpOnly 会话 + CSRF 双提交；登出立刻失效，改口令踢掉所有设备；
- 登录成功与失败都留痕，失败按账号限流；
- 页面上的"审核人输入框"删掉，署名只认会话身份。

### 多实例

审核记录、评测留痕、限流计数全部可落库（`psych.review.store` / `psych.eval.store` / `psych.rate-limit.store`）。
H2 与 PostgreSQL 共用一份 DDL；发现并修掉 H2 不支持 `ON CONFLICT ... DO UPDATE` 的问题——
只有 PG 能跑、本机开发一路正常的那种错，最容易带到上线。

### 证明

`mvn -o test` 194 项（v0.5.0 为 155）。真实实例冒烟：无操作者写操作 401、伪造团队 400、
无 CSRF 403、带 CSRF 签字 200 且署名取自会话。

### 边界

- 容器档与 PostgreSQL 档本版未重跑；ACL 与组织表只在 H2 上验证过；
- 重排未接真模型；离线评估集未扩容，34 条只是管道验证；
- 操作者没有自助注册与找回口令；会话固定 8 小时不滑动续期；
- 前台登录仍为可选，房间页缺少"未登录/已登录"状态提示。

## v0.5.0 完整版

这一版把此前分四轮记录的 v0.4.0–v0.7.0 迭代合并为一次发布。下面按主题归并，每组标题保留合并前的批次；
设计与代码注释里出现的 v0.4.0–v0.7.0 是合并前的内部迭代标记，不代表对外发布过。

### 需求对齐（原 v0.4.0）

这一组只为一份 10 条的作业清单而做。原则不变：能演示、能跑测试、能指出文件，才算对齐；做不到的写清边界，而不是加一个假按钮。

- **语音输入**：房间页加麦克风，走浏览器 Web Speech API（`zh-CN`）在本地转文字，结果落进输入框再发送。**不录音、不上传、不落库**——存音频等于造一个高价值攻击面，作业没有对应链路。
- **情绪刻度**：0–10 由用户点，`mood_points` 落库（JSON 列），单轮内画折线；≤3 分进"关注"状态，只影响后台标记，**不触发安全暂停**（低分不等于危机）。
- **危机卡片**：安全暂停时返回热线、用户自填的联系人、一段可复制的通知文案；后台 `/internal/safety/review` 可见联系人、最近自评，并可标记"已处理"落时间。**不自动外呼**。
- **紧急联系人**：`PUT /api/cbt/sessions/{id}/contact`，只做字符清洗，不做格式校验——校验失败不该让人填不进去。
- **认知偏差**：`DistortionTagger` 9 类规则，从自动思维标出最多 3 个候选，检验阶段在界面上提示；不进总结、不写成诊断。
- **敏感词**：`lexicon/sensitive.txt` + NFKC/零宽/全角/重复字归一化 + block/mask/review 三级动作；输入只跑 in 词，输出只跑 out 词；输出侧命中即触发重写，重写不过走模板。
- **心理专用 System Prompt**：`prompts/cbt/counselor.md` 作为共享前言拼进两处 system（改写、总结），把"不诊断、不用药、不承诺疗效、不制造依赖"集中到一处。
- **持久化**：`cbt_session` 增加 7 个可空列；老库靠幂等 `ALTER ... ADD COLUMN IF NOT EXISTS` 升级，H2 与 PG 同一份脚本。

证据：119 项测试通过（新增 3 个测试类：词库 6 项、偏差 3 项、危机卡片与自评 4 项）；`JdbcCbtSessionStoreTest` 覆盖新列读写；`PromptAssetTest` 继续锁阶段话术结构。

### 账号（原 v0.5.0）

这一组只回答一个被推迟了两轮的问题：**历史记录随账号走，还是随设备走？**
答案是"都走"，但分两个字段记——设备归属不变，账号是叠加的可见范围（[ADR-0009](../03-adr/ADR-0009-账号作为叠加层.md)）。

- **令牌 v2**：设备令牌 `v1` 只签设备 id；账号令牌 `v2` 把设备 id 与账号 id 一起签。
  装设备 id 不是冗余——登录后新开的会话仍要记在这台设备名下，退出登录时才不会从本机消失。
- **认领**：登录/注册时把该设备上 `account_id IS NULL` 的会话挂到账号下，只此一次；
  同一台设备换人登录，后来者不接手前一个人的记录（v0.7.0 起改为显式确认，见下）。
- **可见范围**：设备令牌只看设备名下；账号令牌只看账号名下（不叠加设备归属，否则换账号会漏）；其余一律 404。
- **口令**：PBKDF2-HmacSHA256，120k 次迭代、16 字节随机盐，JDK 自带，不引新依赖；
  迭代次数写进存储串，将来调参时旧口令仍能校验。
- **登录错误不区分**"邮箱不存在"与"口令错"，账号不存在时也跑一次同成本摘要，避免按耗时枚举账号。
- **账号页** `/account/`：登录、注册、已登录状态、退出；登录前的设备令牌单独存一份，退出时换回来。
- **首页入口**：房间右上角一个小点（不写邮箱、不写"已登录"），知识页导航加"账号"。
- **没有做**：找回口令、邮箱验证、令牌吊销、账号注销、第三方登录。缺的不是接口，是发信通道与生命周期策略（v0.6.0/v0.7.0 已补注销、吊销与恢复码，见下）。

- **实跑抓到的两个问题**：`.form{display:grid}` 压过了 `hidden` 属性，登录与注册两个表单会同时出现在页面上；
  账号令牌里带着设备 id，如果可见性写成"设备或账号"，同一浏览器换个账号就能读到前一个人的记录——现在账号令牌只认账号归属。
- **浏览器验收**：房间开会话 → 登录态自动认领 → 页面显示"已认领 1 轮" → 退出后窗外仍能看到这一轮；口令输错时页面就地显示"邮箱或口令不对"。

证据：测试从 119 增至 133 项（令牌往返与防篡改 4 项、账号链路 5 项、账号表 3 项、会话归属 2 项）；
`AccountAuthTest` 覆盖注册认领、第二台设备登录继承、陌生设备 404、重复邮箱与弱口令；
`JdbcCbtSessionStoreTest` 覆盖 `account_id` 落库与只认领未认领会话。

### 收尾（原 v0.6.0）

这一组不引入新流程，只把前几组留下的"还没做"逐条收掉，并且尽量让每一条都能被指到文件与接口。

- **注销账号**：`POST /api/auth/delete`，要口令、要勾选，不可撤销。注销时先解除认领（`releaseAccount`），再删账号；会话不跟着删——第一归属仍是设备（[ADR-0009](../03-adr/ADR-0009-账号作为叠加层.md)）。回跳账号页时会说明"这 N 轮回到本机设备名下"。
- **注销即吊销**：产品接口在验签之后多查一次"账号还在不在"（`CbtController.identity`）。注销把账号删掉，同一枚账号令牌立刻 401——这是本项目第一次真正做到令牌可失效。代价是每请求一次账号查询；规模上来后要换成短 TTL 的缓存，而不是退回不查。
- **窗外翻页**：`GET /api/cbt/sessions/page?limit=&cursor=`。游标是 `(createdAt, id)` 的 base64，不是 offset——一边翻一边新开一轮时，offset 会重复或漏掉一条。`limit` 上限 50，页面默认 40。
- **跨会话情绪趋势**：`GET /api/cbt/mood/trend?days=30`，按本地时区把本人（设备或账号）所有会话里的自评按天聚合，返回均值、最小、最大与次数。窗外左下角画一条线，**没有点的日子就断开**，不插值、不预测、不给"变好了"的结论。
- **词库可改**：`/internal/lexicon.html` 整表编辑，保存即生效。文件 `config/lexicon.txt` 即真值，版本与操作者写在注释头；每次保存留快照；历史里每一版都能回滚；`POST /lexicon/reset` 把随包基线当成一次新的保存。
- **词库门槛**：至少 10 条、至少一条 `block`、至少一条 `in/both`，重复词条、空分类、超长词、含竖线都拒绝。校验不通过时旧表继续跑——"改到一半"比"没改成"危险。历史版本可回滚，回滚是"把旧快照当成一次新的保存"，版本号继续往前走。
- **记录页**：`/internal/record.html?id=`，把一条会话渲染成可打印的 A4 文档：概要、想法链、情绪自评、偏差候选、安全事件与联系人、完整过程、系统轨迹、边界声明。控制台右上角的"记录页 ↗"直接打开。
- **账号视图**：`GET /api/internal/accounts` 与 `/internal/accounts.html`。**只读**，没有"代客注销"——删除别人的账号需要本人口令，不该是内部令牌的一个按钮。"需关注"是名下待处理会话数，不是风险评级。
- **顺手修的**：未知路径以前落到兜底 catch 变成 500（"接口写错了"被报成"服务坏了"），现在 `NoResourceFoundException` 明确回 404。

**实跑抓到的两件事**：词库编辑框最初显示接口的大写枚举（`IN|SOLICIT|BLOCK`），与文件里的小写不一致，人对照文件会以为写错了；现在页面统一小写，保存时再转回枚举。记录页的"安全状态"一开始直接打印 `watch`，改成"关注（自评偏低）"——内部枚举不该出现在给咨询师看的纸上。

证据：测试从 133 增至 143（词库后台 4 项、注销 1 项、翻页与趋势 3 项、会话存储的游标边界与解除认领 2 项）；`LexiconAdminTest` 覆盖"加词下一句就拦下"、四种改坏草稿被拒、回滚生成新版本；`AccountAuthTest` 覆盖注销后旧令牌 401、设备令牌仍能读、口令错不删号；`SessionPagingTest` 覆盖三条会话分三页不重不漏、别人设备的分不进趋势；`InMemoryCbtSessionStoreTest` 锁住"同一时刻创建的两条也必须都能翻到"与解除认领后设备仍可见。H2 档实跑：翻页、趋势、词库保存/恢复、账号注册/注销、记录页与三个新页面均打开正常。

### 真实模型与账号自救（原 v0.7.0）

这一组把"还没做到"里能靠代码与现有资源收掉的，逐条收掉；不能靠代码的（临床签字、发信通道）改成显式状态，而不是假装完成。

#### 模型与向量

- **本机档默认接 Ollama**：`h2` / `pg` profile 默认 `http://localhost:11434/v1`、`qwen3-8b`、`bge-m3`、1024 维；
  `h2,stub` / `pg,stub` 是离线档。容器默认仍是桩，`stack.sh up --ai` 才起容器内 Ollama（拉 1.2 GB + 5 GB）。
- **Qwen3 关闭思考**：`no-think=true` 会在用户消息末尾追加 `/no_think`；不关时 `max_tokens` 被思考链吃光，返回空内容。
- **读取超时**从 30 秒改为可配（默认 120 秒）：CPU 推理一秒几个 token，30 秒会把正常回答误判成故障。
- **模型仪表盘** `/internal/ai.html`：最近 300 次调用的 P50/P95、估算 token、失败数。token 按字符数 / 1.7 估算，页面写明"不是账单"。
  本机 35 次生成：P50 **22.2 秒**、P95 **30.0 秒**；44 次向量：P50 **112 ms**、P95 **195 ms**（Qwen3-8B / BGE-M3，CPU）。
- **向量迁移**：`VectorDimensionMigrator` 在维度不一致时默认只报错不改数据；`psych.ai.vector-migrate=true` 才重建列 + HNSW 并重嵌入。
  在容器 PG 上实跑 256 → 1024：34 块里 17 个非父块重嵌入，检索与问答正常。
- **连接池**从 `DriverManagerDataSource` 换成 HikariCP（默认 20 连接），Tomcat 线程默认 100；两个参数要一起调。

#### 账号自救

- **恢复码**：注册时生成 12 位、只显示一次，存 PBKDF2 摘要；`/api/auth/recover` 用它重置口令，用一次即作废。
  没有 SMTP，所以没有"发邮件找回"；邮箱仍只是登录名。
- **改口令 / 退出其他设备**：令牌里签 `token_epoch`，这两个动作会 +1；旧令牌下一次请求 401，当前设备换新令牌。
- **认领改为显式确认**：登录/注册只回 `pendingClaims`，页面问"要归到这个账号吗？"，用户点确认才认领。
  共享设备"后来者自动接手前一个人未认领会话"的窗口由此关掉。
- **注销即吊销**保留：账号删除后，产品接口查不到账号，令牌立刻 401。

#### 记录与分享

- **一次性分享链接**：`POST /api/cbt/sessions/{id}/share` 生成 24 小时、只能打开一次、可撤回的链接；
  公开页 `/share/` 不需要登录，只能看记录本身——不含联系人电话、内部轨迹、可枚举的会话 id。
- **危机卡**：联系人旁边加 `tel:` 与 `sms:` 入口，正文预填；**发送键仍由本人按**，系统不代发。
- **记录页**保持可打印；分享页复用同一套排版，打印后不再受系统保护，页脚写明。

#### 审核与语音

- **临床审核记录** `/internal/review.html`：按"哪一版"记录审核人、时间、结论与备注；规则/词库改版后自动变"版本已变，需重审"。
  默认仍是"未审核"——系统不能替临床医生签字。
- **Firefox 语音**：Chrome/Edge 继续用 Web Speech；没有 Web Speech 的浏览器录音、重采样成 16k WAV，
  发到本机 `/api/asr/transcribe`，由 Windows `System.Speech`（zh-CN）转写，临时文件即用即删。
  本机实跑：合成"认知检验一般分为五步"，识别为"认真检验一般分为无不"——管道通，准确率不代表可用质量。

### 数据

**正式知识集**（34 条：26 可答 + 8 应拒答，基于仓库内三份示例资料）：

| 配置 | Recall@5 | MRR | 回答率 | 关键词命中 | 引用有效率 | 拒答准确率 |
|-|-|-|-|-|-|-|
| stub-hash-256 | 1.0 | 0.843 | 1.0 | 0.615 | 1.0 | 0.375 |
| bge-m3-1024（检索） | 1.0 | 0.724 | — | — | — | — |
| bge-m3 + qwen3-8b | — | — | 1.0 | 1.0 | 1.0（覆盖率 0.847） | 1.0 |

真向量在这组题上 MRR 反而低于哈希桩（0.724 vs 0.843）：语义召回没丢，但排序被拉平。
这组题只有 34 条、来自示例语料，不能当"BGE-M3 更差"的结论；它说明的是"小集合 + 章节级标准答案"对排序很敏感。

拒答这一列经过三轮才到 1.0，过程本身值得记：
1. 第一轮模型在正文里说"资料不足"，状态却是 `answered` —— 判定只看检索前的证据，没看生成结果；
2. 加"模型自述拒答 → 状态改判"后，拒答到 1.0，但可答率掉到 0.923：有两道题正好在**描述**"系统资料不足时会拒答"，
   全文匹配把正常回答误判成拒答；
3. 改成只看**开头**（前 20 字内的固定前缀），两个指标才同时到 1.0。

这也是"确定性后检"的边界：它能纠状态，不能判断语义；规则越宽，误伤越多。

**三组对照**（4 条小样本：2 可答 + 2 应拒答，同一 qwen3-8b）：

| 组 | 回答率 | 拒答准确率 | 关键词命中 | 平均延迟 |
|-|-|-|-|-|
| A 通用模型直答 | 1.0 | 0.0 | 0.5 | 33.2 s |
| B 通用 RAG（检索 preview 拼上下文） | 1.0 | 1.0 | 1.0 | 6.4 s |
| C 本方案（检索 + 证据判定 + 引用校验 + 拒答后检） | 1.0 | 1.0 | 1.0 | 14.0 s |

A 对两道应拒答题都直接作答，这是"没有证据边界"的典型表现；B 的拒答靠同一模型看片段，C 多了一层确定性判定与引用校验。
B 用 120 字 preview，不是通用 RAG 的上限；4 条也不能当统计结论，只能证明脚本与口径可用。

### 边界

- 模型质量只在 34 条示例题上跑过；CPU 单轮 30–60 秒，不能当生产延迟；
- 拒答准确率提升来自"模型自述资料不足 → 状态改判"的确定性后检，不是模型本身更会拒答；
- pgvector 检索压过 32/64 并发（P95 488/535 ms），但 HNSW 的 `m` / `ef_construction` 未调，大语料重嵌入耗时未测；
- 恢复码是"抄在纸上"的钥匙，丢了仍会丢账号；没有邮箱验证；
- 临床审核有记录、有清单，但没有医生签字，默认仍是未审核；
- 分享链接是一次性明文钥匙，转发即授权；打印后不受系统保护；
- Firefox 语音依赖 Windows 语音包，Linux/容器默认没有；识别准确率未评估；
- 词库门槛是**结构门槛**，不是临床审核；它只保证"输入侧还有人管"，不保证留下的词是对的；
- 趋势按服务器本地时区分天，跨时区看同一天会偏；
- 记录页一旦打印或导出，就不再受系统访问控制保护，转发前要用户自己同意；
- 翻页后新泡泡的位置仍由会话 id 哈希决定，可能与已画的泡泡重叠——这是装饰，不是数据丢失；
- 语音**不录音、不上传、不落库**；紧急联系人只提供 `tel:` / `sms:` 入口，不自动外呼。

## v0.3.1 一键起

这一版只做一件事：把"能跑"变成"一条命令能跑"。功能面没变，变的是运行方式，以及 PG 路径第一次真正跑起来。

- **全部服务进容器**：`Dockerfile` 多阶段构建（Maven 编译 → JRE 运行），非 root，自带 `/actuator/health`；`docker-compose.yml` 起应用 + pgvector/pg16，数据落在 `pgdata` 与 `appconfig` 两个命名卷。
- **一键脚本**：`scripts/stack.sh`（Git Bash/WSL/Linux/macOS）与 `stack.ps1`（Windows 原生）。生成随机密钥的 `.env` → 构建 → 等健康 → 打印入口与令牌；另有 `down`/`reset`/`status`/`logs`/`psql`。
- **可选本地向量**：`docker-compose.ai.yml` 叠层加 Ollama 与 bge-m3，向量变 1024 维真模型；对话仍可独立配置。
- **为跑通 PG 补的两处**：建表 `@Order(0)` 先于种子语料 `@Order(100)`；`vector(n)` 在建表时按 `psych.ai.embedding-dimension` 生成，桩 256 / BGE-M3 1024 都能建。
- **实跑抓到的两个问题**：`# syntax=docker/dockerfile:1` 会强制拉 Docker Hub 前端镜像（国内卡死，已去掉）；embedding 返回空向量时静默生成零长数组（现在直接报错）。

证据（本机 Docker Desktop 实跑）：首次构建 10 分 38 秒、二次 `up` 14 秒；6 张表、3 篇示例文档 34 块、`vector(256)`；检索两路命中带单路分，问答有引用，无关问题判 `insufficient_evidence`；重启容器后会话与轨迹仍在；`down` 后数据卷保留。1024 维用本地假 embedding 等价验证；Ollama 档因镜像下载过慢未跑成，已在 [deploy/README](../../deploy/README.md) 注明。

测试数不变（108 项）：本版没动业务逻辑，新增能力在编排与脚本层。

## 仍未解决

按"会不会影响上线"排序：

1. **真实模型只有 CPU 数据**：qwen3-8b + bge-m3 在本机跑通，单轮 30–60 秒；没有 GPU / 云端 API 的延迟、成本与质量对比，也没有账单级成本核算（本地按 0 元计）。
2. **容器默认仍是桩**：本机 jar 档默认接 Ollama；容器要 `--ai` 才起模型。pgvector 的 `vector(256)` 已有迁移路径并实跑，但默认档与容器档不一致。
3. **正式集仍小**：知识 34 条、安全 25 条、流程 8 条；三组对照只跑了 4 条小样本，不能当"方案优劣"的结论。
4. **pgvector 并发只压了一轮**：会话域 128 并发 0 错误；pgvector 64 并发 P95 535 ms；HNSW 的 `m` / `ef_construction` 未调，大语料重嵌入耗时未测。
5. **认知检验只收反例**：`evidence_for` 仍是空字段，要采"支持证据"得改协议。
6. **账号仍缺邮箱验证**：有一次性恢复码、改口令、退出其他设备、注销；没有 SMTP，邮箱仍只是登录名；没有第三方登录，也没有"只踢掉某一台"。
7. **限流可落库，但仍是固定窗口**：`psych.rate-limit.store=jdbc` 后多实例共享计数，窗口边界可能瞬时放行 2 倍配额；要精确滑动仍需 Redis 或网关。
8. **临床审核仍没有签字**：有按版本的审核记录与清单，默认"未审核"；系统不能替代临床医生做这一决定。
9. **记录页不直接外发**：能打印、能生成一次性链接；打印或另存后不再受系统保护。
10. **语音跨平台**：Chrome/Edge 浏览器识别；Firefox 依赖 Windows 语音包，Linux/容器默认没有。
11. **紧急联系人仍不自动外呼/发短信**：提供 `tel:` / `sms:` 入口，发送键由本人按。
