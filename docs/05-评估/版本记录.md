## v0.3.1 一键起

这一版只做一件事：把"能跑"变成"一条命令能跑"。功能面没变，变的是运行方式，以及 PG 路径第一次真正跑起来。

- **全部服务进容器**：`Dockerfile` 多阶段构建（Maven 编译 → JRE 运行），非 root，自带 `/actuator/health`；`docker-compose.yml` 起应用 + pgvector/pg16，数据落在 `pgdata` 与 `appconfig` 两个命名卷。
- **一键脚本**：`scripts/stack.sh`（Git Bash/WSL/Linux/macOS）与 `stack.ps1`（Windows 原生）。生成随机密钥的 `.env` → 构建 → 等健康 → 打印入口与令牌；另有 `down`/`reset`/`status`/`logs`/`psql`。
- **可选本地向量**：`docker-compose.ai.yml` 叠层加 Ollama 与 bge-m3，向量变 1024 维真模型；对话仍可独立配置。
- **为跑通 PG 补的两处**：建表 `@Order(0)` 先于种子语料 `@Order(100)`；`vector(n)` 在建表时按 `psych.ai.embedding-dimension` 生成，桩 256 / BGE-M3 1024 都能建。
- **实跑抓到的两个问题**：`# syntax=docker/dockerfile:1` 会强制拉 Docker Hub 前端镜像（国内卡死，已去掉）；embedding 返回空向量时静默生成零长数组（现在直接报错）。

证据（本机 Docker Desktop 实跑）：首次构建 10 分 38 秒、二次 `up` 14 秒；6 张表、3 篇示例文档 34 块、`vector(256)`；检索两路命中带单路分，问答有引用，无关问题判 `insufficient_evidence`；重启容器后会话与轨迹仍在；`down` 后数据卷保留。1024 维用本地假 embedding 等价验证；Ollama 档因镜像下载过慢未跑成，已在 [deploy/README](../../deploy/README.md) 注明。

测试数不变（108 项）：本版没动业务逻辑，新增能力在编排与脚本层。

## v0.3.0 知识问答

从"后台能看"推到"用户能问"。功能面首次出现界面分叉：前台走纸本阅读，后台仍是工具控制台，两套不强行统一（[UI 规范 §0](../04-规范/UI设计规范.md)）。

- **用户侧 `/knowledge/`**：提问 → 回答 → 脚注引用 → 右栏出处，证据不足时明确说不足；带移动端布局。房间页左上角补了返回入口。
- **后台 `/internal/knowledge.html`**：看切分（父块 + 子块）、调检索（两路命中与融合分）、试跑问答（回答、引用、校验、轨迹）、入库与审核。新增 `GET /api/knowledge/documents`、`/{id}/chunks`、`/stats`，全部要内部令牌；页面不暴露向量，也不提供删除。
- **向量可分源**：`psych.ai.embedding-base-url/api-key` 与对话分开配置，接 Ollama 的 BGE-M3（1024 维）；对话侧补 `temperature` 与 `thinking-disabled`，兼容只接受固定温度的模型。
- **检索可解释**：命中保留单路原始分（`vectorScore` / `textScore`）；RRF 同分常见，用向量分与 `chunk.id` 兜底排序，同语料每次结果一致。证据判定在真实 embedding 下增加语义相关性门槛（0.55），哈希桩不参与，避免把"共同词多"当成语义相关。
- **评估有骨架**：`run_eval.py` / `ingest_corpus.py`，`dev-v1`（16 条冒烟）与 `who-v1`（20 条真实语料）。

证据：`who-v1` topK=5，stub-hash-256 Recall@5 0.933 / MRR 0.622，BGE-M3 Recall@5 1.0 / MRR 0.822，修掉 3 条口语化误拒。但 5 条无答案题仍被回答，问题从"召回"转到"证据是否真的回答了问题"。

测试从 102 项增至 108 项，新增用例集中在知识库后台接口与知识链路。

## v0.1.0 链路跑通

证明"两个工作流 + 一个知识库"能跑完整一轮。

- 对话：房间页接真实 `/api/cbt/*`，五阶段 + 干预分支 + 中断确认；
- 知识：入库 → 切分 → 检索（向量 + 全文）→ 证据 → 引用校验，证据不足会拒答；
- 存储：`cbt_session` / `cbt_message` / `cbt_turn` 落库，H2 实测重启存活；
- 后台：会话轨迹、输出策略、流程画布三页，改完立即生效。

验收物：6 张界面截图 + 全链路走查，见 [归档原文](../99-归档/v0.1.0-全链路验收.md)。

## v0.1.1 安全加固

跑通之后先堵"能出事"的口子。

| 问题 | 修法 |
|-|-|
| 会话 id 自增、接口无鉴权，可枚举读别人记录 | HMAC 匿名令牌 + 归属校验；不属于本人一律 404；id 加随机后缀 |
| 列表接口不传 userId 返回全库 | 只按令牌身份返回 |
| 内部接口默认开、无鉴权，能改禁句与流程 | 默认关闭；开启必须配令牌，否则启动失败 |
| 知识库 `publish=true` 直通发布 | 入库一律待审核，`/review` 通过才可检索 |
| "他/她/朋友"一出现就放行，"我不想活了，他不知道"会漏判 | 本人意图 HOLD；他人/引用 → REVIEW 队列；补英文与"想消失"等表达 |
| 放行只写字符串，没人看得到 | 待复核队列 + 控制台徽章 |
| 求助信息不可执行 | 12356（全国统一心理援助热线）+ 120 |
| 并发覆盖、写无事务、幂等无界 | 分段锁 + 事务 + 有界幂等 + 限流与长度上限 |
| 「我再改改」是死路 | 编辑态走 `/confirm` 的 `thought` |
| 默认流程缺节点、成环时空白纸片 | 补全拓扑 + 环检测 + 空话术兜底 |

测试从 69 增至 85 项。过程与逐条验证见 [归档原文](../99-归档/v0.1.1-安全加固.md)。

## v0.1.2 后台可控

把"半夜想改、改错会出事"的三样东西交给运维，同时不让它们被改坏。

| 对象 | 可改 | 门禁 |
|-|-|-|
| 安全规则 | 新建/删除/改正则、级别、启停 | 用例回放；至少 1 条 hold 规则 |
| 发布用例 | 增删改文本与期望 | 下限 5 条 HOLD、2 条 PASS，不能删空 |
| 运行参数 | 消息长度、每分钟条数、每小时新会话 | 范围校验 |
| 系统话术 | 6 句非阶段话术 + 占位符 | 键与占位符白名单 |
| 历史版本 | 列表带时间与操作者，可看内容并与当前对比 | 回滚生成新版本，内容同样过门禁 |

"改窄"会被用例指出失效项，"删空用例"被下限拦住，"删掉唯一覆盖某句的规则"同样会被用例挡住——
不靠写死 id，靠行为基线。

测试增至 102 项。逐条验证见 [归档原文](../99-归档/v0.1.2-后台可控.md)。

## 仍未解决

按"会不会影响上线"排序：

1. **模型层是桩**：生成质量、延迟、成本未验证；`http` 档已接真实接口，但没有账单与效果数据。
2. **默认检索仍是哈希向量**：已接 BGE-M3 本地向量（1024 维）并验证，但默认档仍是桩，PG 的 `vector(256)` 还没迁移。
3. **M6 评估有骨架与一组真实基线**：`who-v1` 20 条已跑出哈希 vs BGE-M3 对比；正式测试集、三组对照与真实模型数据仍缺。
4. **PostgreSQL/pgvector 未实跑**：目前用 H2 的 PG 兼容模式验证会话域。
5. **认知检验只收反例**：`evidence_for` 仍是空字段，要采"支持证据"得改协议。
6. **令牌是设备级、不可迁移**：清缓存或换设备即失去旧记录（ADR-0007 明确接受）。
7. **限流是单机的**：多实例部署要挪到网关。
8. **安全规则未经临床审核**：可编辑提高了响应速度，没有改变"规则来自工程常识"这一事实。
