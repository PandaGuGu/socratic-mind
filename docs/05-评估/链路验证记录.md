三条最关键的断言：

1. `recommendationAndConditionMustStayTogether` —— 推荐意见与其否定条件必须留在同一块；
2. `citationNumberOutsidePackIsRejected` —— 回答引用 `[5]` 但只有 2 条证据时，校验必须失败；
3. `draftDocumentsAreNotRetrievable` —— 未发布文档绝不进入检索候选集。

## 3. 端到端（HTTP）

命令：`bash scripts/e2e.sh`（服务已启动）。

### 3.1 知识库现状

```json
{"documents": 4, "published": 4, "chunks": 18}
```

示例语料 3 份（认知模型 / 焦虑表现 / 能力边界），17 个子块；第 4 份是本次脚本上传的草稿。

### 3.2 正常问答

```json
{
  "status": "answered",
  "answer": "根据资料：认知模型通常分三层：最表层是自动思维，中间是中间信念（规则、假设、态度），最底层是核心信念。[1]",
  "citations": [{"number": 1, "documentTitle": "认知行为疗法的认知模型", "section": "三个层次"}],
  "verification": {"allCitationsValid": true, "citationCoverage": 1.0, "invalidCitationNums": [], "unsupportedClaims": []}
}
```

节点轨迹（`trace`）逐条可查：

```
classify_query → cbt_technique
rewrite_query → 自动思维和核心信念有什么区别？ 负性自动思维 认知模型 中间信念 核心信念 认知…
retrieve_evidence → 4 hits
evaluate_evidence → sufficient=true (命中 4 条，相关性 0.39，双路一致=true)
generate_answer → 51 chars, by stub-evidence-grounded
verify_citations → valid=true coverage=1.0
format_response
```

### 3.3 无资料的问题（必须拒答）

```json
{
  "status": "insufficient_evidence",
  "answer": "现有资料不足以回答这一点。\n\n原因：相关性不足（最高 0.06，命中 4 条），按保守策略降级。…"
}
```

注意：**检索仍然命中了 4 条**。如果只看命中数量，这个问题会被"答"出来。判定依据是相关性阈值 + 双路一致，不是"有没有返回结果"——这是本次验证改掉的一个真实缺陷。

### 3.4 草稿闸门

```
上传草稿 → documentId=doc_v4w（status=draft）
提问「固定起床时间对生物钟有什么作用」→ status = insufficient_evidence
审核 approve → status = published
再提问 → status = answered
answer = 根据资料：固定的起床时间比固定的入睡时间更容易维持生物钟的稳定。[1]
verify = {allCitationsValid: true, citationCoverage: 1.0}
```

这条链路证明"上传 ≠ 可检索"不是文档里的一句话，而是代码里的一个过滤条件。

## 4. 本次验证中修掉的缺陷

| 缺陷 | 现象 | 修法 |
|-|-|-|
| 数据源自动配置 | 内存档启动即失败（找不到 DataSource） | 排除 `DataSourceAutoConfiguration`，改为只在 `postgres` 档装配数据源 |
| 证据充分性只看数量 | 无关问题因"命中 4 条"被判为有依据 | 引入相关性阈值（词法重合 ≥ 0.12）+ 双路一致，见 `EvidenceAssembler` |
| 切句吞掉引用 | `结论。[1]` 被切成两句，引用覆盖率算成 0 | 换成正则分词，句末引用并入本句 |
| 引用重复标题 | 引用显示为「书名 · 书名 > 章节」 | 解析时跳过根级标题 |
| 桩输出混入免责声明 | 免责声明被算作"无引用的事实陈述"，污染指标 | 正文只留答案，来源信息放 `generatedBy` |

### 7.2 知识问答的真实输出

```json
{
  "generatedBy": "http:deepseek-flash",
  "answer": "两者不在同一层：自动思维是情境触发后最先冒出的那句评价或预测，核心信念则是对自我、他人和世界的基本判断，位于认知模型的更底层 [1][3]。区别在于：……",
  "verification": {"allCitationsValid": true, "citationCoverage": 1.0,
                   "invalidCitationNums": [], "unsupportedClaims": []},
  "citations": [{"number": 1, "section": "三个层次"}, {"number": 3, "section": "自动思维的特征"}]
}
```

三件值得记下来的事：

1. **模型确实按契约标了 `[1][3]`**，没有出现"参考了相关资料"这种无编号表述；
2. **只回传被用到的 2 条引用**，不是把 4 条候选全塞给前端；
3. 覆盖率 1.0 是在修掉"把邀请当事实主张"的判定之后得到的——第一版把
   "如果你愿意，可以告诉我一个具体场景" 算成了无依据陈述，等于惩罚模型主动追问。

## 8. CBT 流程（M4）验证

新增 `psych-session` 模块与 `CbtFlow`，八个内部阶段压成界面上五颗石子。

### 8.1 一轮完整会话（真实模型）

```
[开始]     情境   ← 问"最近有什么事"
用户: 下周要组会汇报，一想到就手心出汗
[第 1 轮]  想法
用户: 我肯定会在台上卡住，别人都会看出来
[第 2 轮]  检验   ← 提问里引用了用户原话
用户: 其实前三次有两次还算顺利，只有一次超时
[第 3 轮]  行动
用户: 提前写下三条具体预测，会后逐条核对
[第 4 轮]  确认   status=awaiting_confirmation   ← 中断点
```

中断点给用户看的是两条，而不是一条：

```
· 更接近事实的说法：「前三次有两次顺利，只有一次超时，这次会不会卡住、别人是否看得出，还不确定。」
· 行动计划：「提前写下三条具体预测，会后逐条核对」
```

### 8.2 中断与确认的硬约束（都有测试守着）

| 约束 | 断言 |
|-|-|
| 普通消息不得推进确认节点 | 在 `awaiting_confirmation` 下发"行吧就这样"，stage 不变、`userConfirmedThought` 仍为 null |
| 确认只能走 `/confirm` | 未到确认阶段调用 `/confirm` 抛 `IllegalStateException` |
| 确认后才写入 | confirm 之后 `userConfirmedThought == candidateThought`，且两者都可查 |
| 候选想法不是证据原句 | 证据"前三次有两次还行"不得直接成为 `candidateThought` |

### 8.3 安全分流

```
用户: 我真的不想活了，想过结束生命
→ stage=暂停 status=safety_hold
  这超出我能提供的帮助范围了。
  如果你现在有伤害自己的想法，请联系：当地心理援助热线、120，或就近的精神科急诊。
  对话先停在这里。我不会追问细节，也不会做任何判断。
→ 之后再发消息，仍停在 SAFETY_HOLD（不恢复普通流程）
```

第三人称不误报：`看了一部电影，里面有个角色割腕` → 继续普通流程（进入"想法"阶段）。

**这条规则的覆盖面还很窄**，是关键词 + 第三人称排除，必须由专业人员复核后才能上线（见 [安全分流规则](../02-设计/安全分流规则.md)）。
