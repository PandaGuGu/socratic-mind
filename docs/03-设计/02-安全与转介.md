# 安全与转介

这是整个系统里唯一"宁可误报"的地方，也是最容易被做成"谁都不敢聊"的地方。

## 1. 立场

| 已定 | 说明 |
|-|-|
| 只回答"是否转介"，**不做风险等级** | 评级是诊断的边缘形式，误报代价极高（[ADR-0004](../04-adr/ADR-0004-产品边界停在不诊断.md)） |
| 规则通道 + 语义通道 | 规则保证确定性召回，语义补模糊表达（语义通道尚未实现） |
| 触发即暂停普通流程 | 不继续 CBT 步骤，不追问细节 |
| 每轮入口都跑 | 不是只跑第一轮 |
| 转介资源按地区 | 当地急救 / 心理援助热线 / 精神科门诊；不写死某一国家或地区的号码 |

## 2. 规则通道

规则在 `backend/config/safety-rules.json`，后台 `/internal/settings.html` 可增删改，保存即热加载。
执行器 `SafetyScreener`，校验器 `SafetyRulesValidator`。

默认六条规则，按级别分工：

| 级别 | 规则 | 行为 |
|-|-|-|
| `hold` | 自我伤害、伤害他人 | 立即暂停，进转介页 |
| `context` | 指向他人（"我妈不想活了"）、引用语境（歌词/新闻/论文） | **不暂停**，会话置 `review`，进待复核队列 |
| `signal` | 本人意图（"我也不想活了"） | 与 `context` 同现时压过上下文线索，直接 `hold` |
| `ignore` | 口语补语（"累死了""想死你了""死机"） | 匹配前先抹掉，避免把口头禅当自伤 |

三条实现细节，都是踩过坑之后加的：

1. **口语排除在匹配之前。** 不是"命中后再判断"，而是先把"累死了""笑死"抹掉，再跑规则。
2. **第三人称不再一票放行。** 旧版本一出现"他/她/朋友"就放过，"我不想活了，他不知道"会漏判。
   现在：语境指向他人 → 复核；同一句里也表达了自己 → 直接暂停。
3. **放行也留痕。** 被 `context` 放行但值得一看的，记进 `GET /api/internal/safety/review`，
   控制台顶部显示"待复核 N"。只写一个日志字符串等于没人看得到。

## 3. 发布门禁

保存规则前先过两道闸：

| 闸 | 内容 |
|-|-|
| 结构校验 | 正则可编译、级别合法、id 不重复、至少一条启用的 `hold` |
| 用例回放 | 默认 18 条（11 HOLD / 3 NOT_PASS / 4 PASS），逐条比对期望 |

把"我不想活了"改成不再暂停，会被用例直接指出失效项；把用例删空，会被下限拦住。
"改宽"不受限制——多报几个词只增加误报，需要靠复核实测。

历史版本留快照（`config/history/safety/v<n>.json`），回滚是"把旧快照当成一次新保存"，
版本号继续往前走。

## 4. 对用户说什么

固定四段，不临场发挥：

1. 一句共情式承接；
2. 明确说明"这超出我能提供的帮助范围"；
3. 给至少两条可立即使用的路径（当地急救、心理援助热线、就近精神科/急诊）；
4. 不追问、不分析、不给建议。

在房间界面里，这段话不由"小人"说出——**人沉默，房间说话**：
小人停止呼吸动画但不消失，窗外灯光转冷，门边亮起电话剪影，纸片换成转介纸。
让角色说"我帮不了你"，用户接收到的是"陪我的人拒绝了我"
（[界面与交互 §4](04-界面与交互.md)）。

危机卡片同时给出：

- 你所在地区的急救电话与心理援助热线；
- 用户自填的紧急联系人（称呼 / 号码 / 关系）：可以在这一轮里填，也可以在登录后的账号页填一次，
  新开的一轮会带过来；会话里改过的值优先；
- 一段可复制、也可直接用 `tel:` / `sms:` 打开的求助话。

**系统不代发、不代拨。** 自动外呼需要资质与责任约定，误报一次就是真实伤害。

### 为什么不在代码里写死号码

同一个产品可能部署在不同国家或地区，急救与心理援助号码各不相同。写死某一地区的号码，
最坏的结果不是"不精确"，而是让另一个地区的用户在真正的危机里拨到一个错误的地方。

所以代码与话术只给**结构性指引**："你所在地区的急救电话 / 心理援助热线"。
需要给出本地号码时，由部署方按服务地区配置——卡片支持传入自己的清单
（`CrisisCard.of(session, reason, contacts)`），转介话术本身也能在画布或提示词资产里改。
这条与"只转介、不评级"是同一层决定（[ADR-0004](../04-adr/ADR-0004-产品边界停在不诊断.md)）。

## 5. 与会话状态的关系

| 字段 | 取值 | 含义 |
|-|-|-|
| `safetyStatus` | `hold` | 已暂停，输入锁定 |
| `safetyStatus` | `review` | 放行但需人工看，出现在待复核队列 |
| `safetyAckAt` / `safetyAckBy` | 时间 / 人 | 后台"标记已处理" |

命中 `hold` 后，流程停在 `SAFETY_HOLD`（终态），后续消息不会把对话拉回普通流程。
是否允许恢复，仍是待决项（[CBT 状态机 §4](01-CBT状态机.md)）。

情绪自评 ≤3 只把会话标成"关注"，**不触发暂停**——低分不等于危机。

## 6. 必须承认的局限

- 规则与用例来自工程常识，**没有临床审核**；用例可改，所以"基线"最终仍由人定；
- 语义通道未实现，模糊表达（"活着没意思"）只能靠规则覆盖到的说法；
- 改宽没有上限，误报只能靠复核实测；
- 安全测试集只有 25 条，召回 1.0 是"在小样本上"，不是承诺；
- 没有真人兜底，也没有与任何急救系统的对接。

上线前的硬门槛：语义通道、专业人员复核、更大的安全测试集与双指标（召回 / 误报）。
