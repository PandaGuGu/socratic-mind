# 内部后台

> 入口：`GET /internal`（`psych.internal.enabled=true` 时注册）。
> 读者是作者、评审与运营，**不是用户**。本页不适用 [UI 设计规范](../05-规范/02-UI设计规范.md) 的前台语言。

产品界面回答"这句话凭什么这么说""我刚才说了什么"；后台只回答一件事：
**这一轮到底走到哪一步、为什么走这一步。**

## 1. 三层，顺序不能反

| 层 | 载体 | 缺了会怎样 |
|-|-|-|
| 事件 | `CbtTurnEvent`（每轮一条） | 只有字段快照，"第 3 轮为什么被拦住"永远说不清 |
| 接口 | `/api/internal/*` | 事件只在内存里，没有读取面 |
| 视图 | `/internal` 静态页 | 有数据没人看，等于没做 |

只有视图没有事件，就是摆拍。

## 2. 事件模型

`CbtMessage` 与 `CbtTurnEvent` 分工明确：

| | `CbtMessage` | `CbtTurnEvent` |
|-|-|-|
| 记什么 | 说了什么 | 为什么这么走 |
| 谁看 | 用户、咨询师 | 作者、评审 |
| 能否导出 | 能，属业务事实 | 不必，属运行时审计 |
| 粒度 | 一条消息一条 | 一轮一条 |

| 字段 | 取值 | 说明 |
|-|-|-|
| `turnNo` | 连续整数 | 后台按它排序，不跳号 |
| `action` | `start` / `answer` / `blocked` / `safety_hold` / `confirm` / `end` | `blocked` 专指被中断点或终态挡住，与正常回答区分 |
| `stageFrom` → `stageTo` | `CbtStage` | 首轮 `stageFrom` 为空 |
| `safetyRule` | 规则 id / 空 | 放行也留痕 |
| `modelMode` | `model` / `template` / `none` | 这句是模型写的、模板兜底的，还是没调模型 |
| `latencyMs` | ≥0 | 端到端耗时，不是模型耗时 |

## 3. 状态由后端推导，前端不猜

链路轨道的六种状态全部由 `trace` 与 `session` 推出，不读文案、不做关键词匹配：

| 状态 | 判定 |
|-|-|
| 已完成 | `stage` 出现在 `visited` 中，或当前阶段已结束 |
| 进行中 | `stage === 当前阶段` 且未结束、未等确认 |
| 等确认 | 当前阶段是中断点且 `awaitingUser` |
| 未进入 | 既不是当前阶段，也不在 `visited` 中 |
| 安全暂停 | 当前阶段是 `SAFETY_HOLD`，标红 |
| 未走这条 | 仅用于分支：由 `interventionType` 直接给出 |

两个细节：**"未走这条"必须与"未进入"区分**（否则用户以为漏了一步）；
**分支同目标只标一条**（避免"两条都走了"的错觉）。

## 4. 页面

| 页面 | 用途 | 关键边界 |
|-|-|-|
| `/internal` | 会话列表、阶段链、逐轮轨迹、待复核 | 只读会话状态 |
| `/internal/settings.html` | 安全规则、用例、限流、系统话术、历史与回滚 | 保存前跑用例 |
| `/internal/lexicon.html` | 敏感词库整表编辑、试跑、恢复基线 | 结构门槛，不是内容审核 |
| `/internal/knowledge.html` | 切分预览、检索调试、问答试跑、入库与审核 | 不暴露向量、不提供删除 |
| `/internal/flow.html` | 流程画布：改话术、去向、分支、起点 | 分支目标受白名单约束 |
| `/internal/policy.html` | 输出策略：档位、禁句、重合度阈值、试跑 | 命中能重写就重写，否则回模板 |
| `/internal/eval.html` | 四格指标、badcase 池、确定性抽样 | 不合成总分 |
| `/internal/review.html` | 六类对象的审核留痕与清单 | 默认"未审核"，系统不替人签字 |
| `/internal/accounts.html` | 账号数、会话数、"需关注"计数 | 只读，没有代客注销 |
| `/internal/members.html` | 成员与职责：新建、撤销、重设口令 | 只有管理员；不能撤销自己 |
| `/internal/ai.html` | 延迟 P50/P95、估算 token、失败数 | token 是估算，不是账单 |
| `/internal/record.html?id=` | 可打印的 A4 记录页 | 投影，不是新数据；无外发通道 |

### 4.1 角色与职责（v0.7）

后台不是一个"超级管理员"包打天下。四种身份，一件事只归一个人：

| 职责 | 看得到 | 能改 | 不能 |
|-|-|-|-|
| 管理员 `admin` | 全部 | 成员与口令、会话原文/导出（破窗） | —— |
| 运营 `operator` | 会话**列表**（不含原文）、知识库、配置面 | 入库、可见范围、流程画布、输出策略、话术、安全规则、运行参数、词库、模型、评测 | 知识发布/退回、读会话原文 |
| 审核 `reviewer` | 知识库、待复核队列、**安全标记会话的原文** | 知识发布/退回、安全提示确认 | 任何配置、入库、成员、普通会话原文 |
| 只读 `viewer` | 同运营的可见范围 | —— | 一切写操作 |

执行只有两处，判断不散在业务代码里：

1. `InternalAuthInterceptor` 先挡 `viewer` 的一切写操作；
2. 再按 `@RequirePerm` 挡"这件事归谁"——权限矩阵只有 `Operator.allows(Perm)` 一份。

被拒时返回 `403` + `{"code":"ROLE_FORBIDDEN"}`，message 直接给人看（"这个操作需要「运营内容」职责，当前身份是审核"）。
前端只负责隐藏按钮，判权永远在服务端；`InternalEndpointPermTest` 会遍历 `/api/internal` 下的写接口，
漏标职责的接口让构建失败——这条规则是两次真实疏漏换来的。

会话**原文**是单独一道门（`SESSIONS_CONTENT`）：列表只回答"有哪些会话"，`targetProblem` 对无权限者置空；
原文、轨迹、原始 JSON、导出默认只给管理员，审核者的例外仅限 `SAFETY_HOLD` / `hold` / `review` / `watch` 的会话。

新增成员在「运营 → 成员」：姓名、职责、登录名、初始口令由管理员当面设定（系统没有发信通道），
撤销会立刻让该成员的所有设备下线。

## 5. 配置面：同一套约定

安全规则、运行参数、系统话术、词库、画布、输出策略，全部走同一套：

| 约定 | 含义 |
|-|-|
| 文件即真值 | 改动落在 `backend/config/*.json`，可进 git、有 diff、能 review |
| 保存即生效 | 热加载，不重启 |
| 坏文件不生效 | 解析或校验失败时保留上一版并告警 |
| 留快照 | 每次保存一个版本，带时间与操作者 |
| 回滚 = 新保存 | 版本号继续往前走，不改写历史 |
| 服务端拒绝 | 不靠人记得住底线，靠校验与用例 |

### 5.1 规则与参数

| 区块 | 能改 | 门禁 |
|-|-|-|
| 安全规则 | 级别、正则、启停、增删 | 结构校验 + 用例回放；两条 hold 规则不许删/关 |
| 运行参数 | 消息长度、每分钟条数、每小时新会话 | 范围校验 |
| 系统话术 | 结束语、待确认拦截、确认回执、平衡与总结模板 | 键白名单 + 占位符白名单 |

历史不是一串编号：列表带时间与操作者，点开可与当前逐项对比，差异高亮，可直接从对比面板回滚。

### 5.2 词库

一行一条 `scope|category|action|word`，与 `config/lexicon.txt` 同构。
保存要求：至少 10 条、至少一条 `block`、至少一条 `in/both`。校验不过，旧词库继续生效——
"改到一半"比"没改成"危险得多。

它只是结构门槛，不是内容审核：留下的词对不对、宽窄是否合适，仍然要人看。

### 5.3 流程画布

能改：每节点标题与话术（支持 `{{thought}}` / `{{plan}}`）、节点位置、下一步、
是否调模型（`none` / `cbt_balance` / `cbt_summary`）、按干预类型分支、增删可选节点、判断条件。

不能改：八个主干节点不能删；字段语义由代码定；安全分流不在画布上（每轮硬跑）；
确认中断不能被绕过。

**为什么分支只能连到白名单节点**：每个节点写的是不同的类型化字段——情境写 `targetProblem`、
想法写 `automaticThought`、检验写 `candidateThought`。把"检验"连回"想法"，证据会覆盖自动想法；
连到"总结"，候选说法永远为空。平台的节点是自包含函数，连错只是跑错；
这里的节点是状态机的步骤，连错会产生空字段和不可解释的记录。

发布前四类校验见 [流程与状态 §7](../02-架构/02-流程与状态.md)。

### 5.4 输出策略

```
CbtFlow / RagService
      │ chat(system, user, "cbt_balance")
      ▼
GuardedChatPort          ← 所有模型调用的唯一闸门
      ├── OutputPolicyStore   读 JSON、按 mtime 热加载、坏文件不生效
      ├── GuardRules          纯函数：长度 / 禁句 / 与输入重合度
      └── GuardAuditLog       最近 200 条：通过 / 重写后通过 / 拦截
      ▼
StubChatPort / HttpChatPort
```

命中后的处理是固定的：**能重写就重写，重写不过就退回模板**。用户永远不会看到被拦下的那句。

三个刻意的设计：

1. **规则即数据。** 策略文件进 git，页面上改的和文件里写的是同一份东西；
2. **坏文件不生效。** 避免一次手滑把所有档位关掉；
3. **拦截必须留痕。** 同时进轮次轨迹的 `guardRule` 与守卫审计——只看一处都会得到片面结论。

为什么不做成拖拽连线：流程编排面向开发（出错是跑不通，测试能发现），
输出策略面向运营（出错是用户看到不该看的话）。两者需要的形式不同。

## 6. 审核与评测

| 机制 | 做法 | 为什么 |
|-|-|-|
| 审核留痕 | 记录对象版本、审核人、时间、结论、清单勾选 | "改版即重审"只是状态，证明不了有人真的看过 |
| 署名 | 取自登录身份，页面没有"审核人"输入框 | 输入框等于可以替别人签字 |
| ACL 快照 | 审核记录里存签字那一刻的可见范围 | 回填当前值会让历史签字随现状漂移 |
| 评测指标 | 回答率 / 拒答率 / 引用有效率 / 待处理样本，分开报 | 合成一个 0.83 看不出哪一段在变差 |
| badcase 池 | 拒答、引用不成立、管道异常自动进池 | 拒答不等于错误，但永远值得看一眼 |
| 抽样 | 固定步长，不随机 | 随机会让今天和昨天看的不是同一批 |

审核的对象是六类：安全规则、词库、流程、输出策略、限流参数、会话复核。
默认状态是"未审核"，系统不能替临床医生签字。

## 7. 只读边界与部署

"只读"指**会话业务状态**，不是配置：

- 不提供任何改写会话状态的接口；用户确认仍只能走 `/api/cbt/sessions/{id}/confirm`；
- 可以改的是配置：安全规则、运行参数、系统话术、输出策略、流程定义、词库；
- "生成演示会话"调用真实流程，脚本化的只是输入消息，页面标「演示」；
- 记录页可打印/存 PDF，但不替用户外发。

```yaml
psych:
  internal:
    enabled: false            # 默认关闭；false 时 /internal 与 /api/internal 都不注册
    token: ${PSYCH_INTERNAL_TOKEN:}   # 开启时必填，否则启动失败
```

开发档（h2 / pg / http）代为打开并给默认令牌 `dev-internal-token`，同时开 `dev-hint`：
页面启动时取默认令牌自动填入。该接口只在"开关打开**且**令牌仍是默认值"时返回内容；
换过令牌即返回空，鉴权本身不受影响（[ADR-0007](../04-adr/ADR-0007-会话归属与内部接口鉴权.md)）。

顶栏三个徽章不是装饰，是防止演示被当成生产：**内存档 · 重启即丢**、**桩模型**、**内部令牌已启用**。
