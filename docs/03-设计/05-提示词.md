# 提示词

提示词不写进 Java 字符串常量，按文件管理：可 diff、可 review、可被测试锁住结构。

## 1. 现状

```
backend/psych-agent/src/main/resources/prompts/
├── cbt/
│   ├── counselor.md   共享前言：不诊断、不用药、不承诺疗效、不制造依赖
│   └── stages.md      各阶段话术与安全转介话术，带 [stage:xxx] 锚点（现为 9 段）
├── free/companion.md  门外自由对话的边界：一次一问，不诊断、不劝、不承诺疗效
└── ../psych-rag/src/main/resources/prompts/knowledge/generate-answer.md
                       知识问答生成：只依据证据，不足即拒答
```

`counselor.md` 拼在每处模型调用的最前面。改边界只改一个文件，两处调用同时生效——
之前"不许做什么"分散在两条任务说明里，改一处会忘另一处。

`stages.md` 由 `PromptAssetTest` 锁结构：锚点必须齐全、占位符必须认识、不能出现 CRLF。
锁结构不锁哈希：改措辞不必改哈希，改结构才会让测试红。

> 门外与知识问答的提示词在首次启动时以这些文件为默认值，之后由后台「规则与参数」维护：
> 保存写入 `config/prompts.json`（随包文件不改），即时生效，带版本号与署名。
> 分类与改写仍是规则实现，只有生成这一句走模型。

## 2. 文件格式

```markdown
---
prompt_id: cbt_cognitive_review
version: 1.2.0
language: zh-CN
node: COGNITIVE_REVIEW
output_format: text
---

## 角色
（该节点扮演什么）

## 输入
（注入的字段名，逐个列出，不要写"上文"）

## 任务
（步骤化的动作）

## 约束
（禁止事项，尤其是"不得推断""不得补充证据"）

## 输出契约
（字段清单 + 一个正例）
```

| 字段 | 必填 | 约束 |
|-|-|-|
| `prompt_id` | 是 | 全局唯一，`{graph}_{node}` |
| `version` | 是 | 语义化版本 |
| `node` | 是 | 必须与 [流程与状态](../02-架构/02-流程与状态.md) 的阶段枚举一致 |
| `output_format` | 是 | `text` / `json`；json 必须给 schema 或示例 |

## 3. 版本号

| 变更 | 版本位 |
|-|-|
| 改输出字段、改步骤、增删约束 | minor +1（`1.1.0 → 1.2.0`） |
| 仅措辞、示例、标点 | patch +1（`1.2.0 → 1.2.1`） |
| 换节点职责 / 换输出格式 | major +1，且必须新增评估记录 |

## 4. 硬性约束

1. **不写模型名、温度、max_tokens**：这些属于节点配置，不属于提示词。
2. **不写"请参考以上内容"**：输入必须显式列出字段名，变量用 `{{field}}`。
3. **安全规则只在 `counselor.md` 维护**，阶段文件不重复抄写。
4. **涉及证据的节点必须写"证据不足时如何回答"**，默认动作是"说不知道"，不是"合理推测"。
5. **不得要求模型输出它无法知道的东西**：推荐强度、证据等级只能转述原文，缺失即 `null`。
6. **不把流程写进提示词**："下一步该问什么"由代码决定，提示词只负责这一句怎么说。

## 5. 变更流程

```
改 prompt → 跑该节点的评估子集 → 记录结果 → 通过则升版本号并提交
                                      └→ 不通过则回滚，保留改动记录
```

评估集与指标见 [评估与测试集](../06-评估/02-评估与测试集.md)，结果留档在 `eval/results/`（不入库）。

## 6. 命名

- 文件名：`kebab-case.md`；
- `prompt_id`：`{graph}_{node}` 蛇形，如 `cbt_cognitive_review`；
- 文件名与 `prompt_id` 必须能互相推导，禁止两个名字对不上。
