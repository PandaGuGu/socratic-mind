# 界面与交互

> 原型：`frontend/preview/world-demo.html` 与 `ui-demo.html`（可直接打开）。
> 视觉 token 见 [UI 设计规范](../05-规范/02-UI设计规范.md)；本文只说空间与叙事。

## 1. 一条原则：房间是家，泡泡是产物

**默认界面是房间，不是星图。** 打开产品看到的是同一间屋子、同一个坐在墙角的人；窗外一开始是空的。

| 理由 | 说明 |
|-|-|
| 没有"选哪个"的成本 | 星图当首页，用户每次要先判断"今天进哪个泡泡" |
| 空状态不尴尬 | 面对空星图会以为产品坏了；面对空房间只是"还没聊过" |
| 泡泡因此有含义 | 泡泡不是系统生成的条目，是你说过的话堆出来的东西——这让星图变成回忆，而不是任务列表 |

一句话：**房间是入口，窗外是记忆。** 永远从"现在"进入，从"过去"回看。

## 2. 空间与数据

| 界面元素 | 隐喻 | 对应数据 |
|-|-|-|
| 房间 | 家 | 无，常驻；不随会话切换 |
| 小人 | 引导者 | 当前阶段；无面孔、无名字、不主动开口 |
| 纸片 | 一句话 | 本轮 `response` + 选项；一次只出现一张 |
| 飞出的纸片 | 说出去的话 | 一条 `cbt_message` |
| 窗外的光点 | 一句话的痕迹 | 消息聚合展示 |
| 泡泡 | 一次对话 | 一行 `cbt_session`，轮次越多越大 |
| 丝线 | 同一主题 | 共享 `targetProblem` 的会话 |
| 石子 | 进度 | `visibleIndex`：8 个内部节点压成 5 段 |
| 门 | 结束这一轮 | 随时可走，离开不是失败 |
| 窗 | 历史 | 点开才看，不主动推送 |

**一间房，不是每件事一间房。** 多房间会把"同一个墙角的人"变成 NPC 集合，
也让用户每次多一次选择。不同的事由泡泡承载，不由房间承载。

**房间不堆积，是这套设计的核心。** 传统聊天界面把 40 条历史压在屏幕上，本身就在传递"你欠了很多"。
这里的规则相反：说出去的话会飞走，房间永远只有当前这一张纸。代价是房间内不能回翻，
所以窗必须随时可点，且翻到的内容要能定位回那一刻。

## 3. 视觉编码的禁区

| 禁止 | 原因 |
|-|-|
| 泡泡大小表示"严重程度" | 变相分级，违反 [ADR-0004](../04-adr/ADR-0004-产品边界停在不诊断.md) |
| 颜色表示情绪 | 同上；情绪是私密信息，不该被系统标注 |
| 长期未处理的泡泡枯萎 | 制造内疚，与产品定位相反 |
| 未读红点、待办角标 | 把陪伴变成 KPI |
| 删除泡泡的动画 | 会被理解为"这段经历被抹掉了" |

允许的编码只有三种：**大小** = 这次对话的轮次（投入，不是严重度）；
**亮度** = 是否还在进行；**虚实** = 这一轮的泡泡还没成形。

丝线只表示"同一主题"。时间顺序会连成进度条，因果关联需要模型推断心理状态，都不做。
**宁可稀疏，不要画成蜘蛛网。**

## 4. 安全转介：人不能开口说"我帮不了你"

如果让墙角的人说出"这超出我的范围，请拨打…"，用户接收到的是**"陪我的人拒绝了我"**。

正确做法是**让人沉默，让房间说话**：

| 元素 | 变化 |
|-|-|
| 小人 | 停止呼吸动画，仍在原处，不消失、不背对 |
| 窗外的光 | 由暖转冷 |
| 门边 | 亮起一盏小灯 / 电话剪影 |
| 纸片 | 换成固定转介纸（热线、就近门诊），没有输入行 |

一句话：**"人没走，是房间把门打开了。"**

## 5. 引用怎么放

房间里不出现证据栏，否则又变回密集界面。引用降级为**纸片角上的一枚书签**：
点开是一张更小的纸（来源、章节、页码），看完即收。

证据必须在，但不必同时全部在场。

## 6. 熵控制

| 规则 | 做法 |
|-|-|
| 上限 | 默认显示最近 12 个泡泡，更早的收进"更早" |
| 漂移 | 30 天未进入的泡泡向外、变暗，但不消失 |
| 位置稳定 | 坐标由 `sessionId` 哈希确定性生成；刷新、换设备都不移动 |

**位置一变，空间记忆就废了**，这是这类界面的生命线。

## 7. 降级路径

| 需要 | 做法 |
|-|-|
| 无障碍 | 窗外提供等价的语义列表（时间 + 主题 + 阶段），读屏可遍历 |
| 不接受隐喻 | 切"列表模式"，回落到三栏界面；两种模式共用同一份数据 |
| 低性能设备 | 关闭浮动与粒子，静态星图 |
| 首次使用 | 第一屏只给一句提示，第三次进入后不再显示 |

## 8. 已实装

`GET /` 与 `/room/` 落到 `backend/psych-app/src/main/resources/static/room/index.html`，
页面直接调 `/api/cbt/*`，没有假数据。

| 元素 | 数据来源 |
|-|-|
| 纸上那句话 | `POST /api/cbt/sessions` 的 `response`，之后是每轮的 `response` |
| 石子进度 | `visibleIndex` + `stageLabel`；`SAFETY_HOLD` 全灭 |
| 起手三句 | 仅第一问的快捷回复，之后自由输入 |
| 确认条 | `awaitingConfirmation`；两个按钮走 `/confirm` |
| 安全暂停 | `stage === SAFETY_HOLD`：停呼吸、窗口变冷、输入禁用 |
| 窗外泡泡 | `GET /api/cbt/sessions/page`；大小 = 轮次，位置 = `hash(sessionId)` |
| 纸片回看 | `GET /api/cbt/sessions/{id}` 的消息流 |
| 连接状态 | 每次请求的结果；左下角一行字，失败变红，不弹窗 |

边界：房间只用 `/api/cbt/*` 与 `/api/knowledge/*`，不碰 `/api/internal/*`；后台也不引用房间样式。
两边共用接口，不共用视觉。
