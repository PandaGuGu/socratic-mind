# 方案对比：为什么是这个形态

本文只回答一个问题：**在已有方案里，本方案为什么站在这个位置。**
结论先行：它把 Wysa 式的"神经符号混合"用开源 Java 栈重做了一遍，并把"临床审核话术库"换成
"可版本化、带证据属性的审核知识库"——用工程换内容扩展性，代价是放弃临床证据与真人兜底。

## 1. 先分层，再比较

现有心理 AI 方案不在同一层面上，拉一张功能表对比没有意义。

| 层次 | 代表 | 优化的目标 | 不负责 |
|-|-|-|-|
| 模型层 | SoulChat、EmoLLM、MindChat；通用大模型 + 提示词 | 说得像不像一个会共情的人 | 出处、流程、审计 |
| 平台层 | Dify、RAGFlow、FastGPT、LangGraph / Spring AI Alibaba Graph | 多快能搭出一个 AI 应用 | 业务状态是否可控、结论是否合规 |
| 产品层 | Woebot、Wysa、Therabot、Deprexis、国内平台型产品 | 能不能进医院、企业、医保 | 技术是否可复用、能否私有化 |

四条判据比"功能有没有"更有区分度：

1. **证据可溯源性**：能不能指回具体文献的具体页码或章节；
2. **流程可控性**：业务状态在代码或数据库里，还是只在模型上下文里；
3. **能力边界**：敢不敢说"我不知道""这超出范围"；
4. **落地成本**：人月、许可、算力、知识更新代价。

大多数公开对比只比第 1 条的一半和第 4 条，所以结论常常是"开源方案都能做"。
把第 2、3 条摆上桌，三类方案立刻分化——分化的位置就是本方案站的位置。

## 2. 模型层：模型是门槛，不是差异

| 方案 | 路线 | 强项 | 对本项目的缺口 |
|-|-|-|-|
| SoulChat 1.0 / 2.0 | 真实咨询语料 + 咨询师数字孪生（约 9 万轮），全量微调 | 认知共情、谈话技术、语言风格 | 无出处、无证据分级、无结构化阶段；7B 级长文理解偏弱 |
| EmoLLM / MindChat | 心理支持指令微调 | 覆盖面、拟人度、中文自然 | 定位是情绪支持，不管疗法依从性与流程 |
| ChatCounselor / CPsyCoun / PsyChat 等 | 真实或合成咨询对话微调 | 单轮咨询话术 | 多为 7B 模型，缺工程化、安全网关与审计 |
| 通用模型 + 提示词 | 纯提示词工程 | 流畅度、建议有效性最强 | 幻觉、无出处、边界完全依赖提示词，不可回归测试 |

**共同天花板：它们把心理支持当成"对话质量问题"来解。** 而本项目要解的三个问题——
"这句话出处是哪一页""用户走到第几步""这句结论该不该说"——一个都不在它们的损失函数里。

ESC-Eval 一类评测显示：垂域微调模型在"拟人度、以人为中心"上优于通用模型，但在流畅度与建议有效性上并不占优。
**微调换来的是风格，不是可靠性**，所以本方案不把"微调一个心理模型"作为主线
（[ADR-0003](../04-adr/ADR-0003-不微调垂直模型走RAG.md)）。

本方案对模型只有三条要求：

| 门槛 | 第一版要求 | 排除了什么 |
|-|-|-|
| 通用能力 | 不低于同代通用中文模型 | 7B 级垂域微调模型作为主模型 |
| 响应延迟 | 首 token P95 < 1.5s，单轮 < 4s | 每节点多次反思、多 Agent 辩论 |
| 可替换性 | 通过 `ChatPort` 接入，按节点配模型 | 把模型能力写进业务逻辑 |

推论：**延迟是预算，不是优化项。** 一个节点最多一次主模型调用，检索与引用定位全走确定性代码——
这正是 [流程与状态 §3](../02-架构/02-流程与状态.md) 里"哪些节点不调模型"的原因。

## 3. 平台层：实现手段，不是竞争方案

| 方案 | 定位 | 多轮挂起 / 恢复 | 许可 | 在本项目中的用法 |
|-|-|-|-|-|
| Dify | LLM 应用平台 | 会话 = 消息历史，无节点级 checkpoint | Apache-2.0 修改版，多租户运营需授权 | 只用来搭对照组的 B 组 |
| RAGFlow | 深度文档理解 | 无 | Apache-2.0 | 可选的离线解析外包（扫描件、复杂表格） |
| FastGPT / MaxKB | 知识库问答 + 工作流 | 无 | 附加条款较严 / GPLv3 | 不建议，授权会挡路 |
| LangGraph（Py/JS） | 低层状态编排 | checkpoint + interrupt | MIT | 若转 Python 栈是首选 |
| Spring AI Alibaba Graph | Java Graph runtime | checkpoint 持久化 | Apache-2.0 | 目标选型；当前实现未引入（见 ADR-0002 备注） |

两条必须讲清楚的判断：

> **低代码平台把"会话"建模成消息历史，而 CBT 需要的是可暂停、可回滚、可确认的业务状态机。**
> 用户说"我想改一下刚才那个想法"，平台只能把历史重喂给模型再生成；这里是两个字段分开存，
> 改的是字段，不是重跑对话。这是数据模型的差别，不是实现细节。

> **平台的证据单元是 `chunk + metadata`。** 要表达"适用于哪个人群、推荐强度多高、有哪些限制"，
> 只能塞进 metadata 字符串再指望模型别搞错。`kb_evidence` 把这些拆成结构化字段，无法确认就存 `null`。

平台层不参与打分，只决定"借哪些零件、什么时候重判"：现在借 RAGFlow 的解析思路与 Dify 做对照，
是否整体换成平台底座，取决于 [§7 三组对照](#7-把对比做成实验三组对照)的结果。
触发条件：B 组与本方案的引用支持率差距小于 5pp 时，自研 RAG 的增量不足以支付维护成本；
差距大于 15pp 且主要来自证据结构化时，维持自研。

## 4. 产品层：三条路线，本方案选第二条

| 产品 | 形态 | 技术路线 | 证据基础 | 启示 |
|-|-|-|-|-|
| Woebot（2017–2025） | C 端 CBT 机器人，2025-06 关停 C 端 | 脚本化决策树 + 临床审核话术 | 多项 RCT；FDA 突破性器械认定，未获批 | 脚本化可控但扩展性差；停运原因是上市许可成本 + LLM 监管路径未明 |
| Wysa | C 端 + B 端（NHS 分诊入口） | 神经符号混合：审核话术 + 决策树 + 受约束生成 | 30+ 篇同行评议；FDA 突破性器械认定 | **与本项目最接近的工程范式** |
| Therabot | 研究型生成式治疗对话 | 微调 LLM + CBT/DBT 框架约束 | 2025 NEJM AI 的 8 周 RCT | 路线成立，代价是临床团队 + RCT 预算 |
| Deprexis | 德国数字疗法（可处方） | 线性模块化 CBT，几乎不依赖生成 | 多项 RCT；德国 DiGA 报销 | 疗法保真度靠固定模块，不靠模型自觉 |
| 国内平台型 | 平台 / 医疗 / 校园 | 自研模型 + AI 分诊 + 真人兜底 | 多为厂商自述 | 没有一家把"AI 独立治疗"当卖点 |

抽象成三条架构路线：

| 范式 | 代表 | 可控性 | 覆盖面 | 成本 | 主要失效模式 |
|-|-|-|-|-|-|
| A. 脚本决策树 | Woebot、Deprexis | 最高 | 最窄 | 内容生产成本极高 | 用户一偏题就僵住；知识更新 = 重写脚本 |
| B. 神经符号混合 | Wysa | 高 | 中 | 中 | 骨架质量决定上限 |
| C. 端到端生成 + 框架约束 | Therabot、纯提示词 | 低 | 最宽 | 开发低、验证高 | 幻觉、越界、不可回归测试 |

本方案是 **B 的一次开源栈重实现**，关键替换在于符号层的载体：

- Wysa 的符号层是**人工审核过的话术库**，能保证每句话都被临床团队看过，代价是每个新场景都要重写；
- 本方案的符号层是**流程结构 + 审核过的证据库**，骨架是代码，内容来自可版本化的知识库。
  新增一种干预方式不需要改代码，只需要入库一份带证据属性的文档。

代价同样明确：没有临床团队、没有 RCT、没有牌照、没有真人兜底。

## 5. 九维总表

图例：● 原生支持　◐ 需自行实现 / 部分支持　○ 不具备

| 维度 | 垂直模型 | 低代码平台 | 编排框架 | 闭源产品 | **本方案** |
|-|-|-|-|-|-|
| 出处可溯源到页码 | ○ | ◐ 有 chunk 引用 | ○ | ◐ 内部有，未开放 | **●** `kb_citation` + 引用校验 |
| 证据结构化与分级 | ○ | ○ | ○ | ● 人工审核话术 | **●** `kb_evidence` |
| CBT 阶段可控 | ○ | ◐ 靠提示词 | ● 状态图 | ● 决策树 | **●** `CbtFlow` + 显式字段 |
| 跨轮挂起与恢复 | ○ | ○ | ● checkpoint | ● | **●** 会话字段 + 逐轮事件 |
| 用户确认可追溯 | ○ | ○ | ◐ 需自建业务表 | ● | **●** `userConfirmedThought` 独立字段 |
| 安全分流 | ◐ 靠对齐 | ◐ 靠提示词 | ◐ 需自建 | ● 规则 + 人工升级 | **●** 规则通道 + 每轮硬跑 |
| 私有化 | ● | ● | ● | ○ | **●** Java 单体，可离线 |
| 许可风险 | ● | ◐ 有 SaaS 条款 | ● | ○ | ● 依赖均为宽松许可 |
| 冷启动成本 | 高 | **最低** | 中 | 不适用 | 中高 |
| 临床证据 / 真人兜底 | ○ | ○ | ○ | ● | **○ 明确不承诺** |

三条结论：

1. 在"可控 + 可审计"两列，低代码平台是空缺的，而这是心理场景的硬需求；
2. 在"冷启动成本"和"临床证据"两列，本方案明确劣势，短期补不上；
3. 唯一"别人都没有"的组合是**出处可溯源 + 证据分级 + 流程状态机同时成立**。单看任何一维都有替代品。

## 6. 必须承认的短板

| 短板 | 差距 | 第一版怎么办 |
|-|-|-|
| 共情表现 | 通用模型 + 提示词大概率弱于微调模型与商业产品 | 不追求"像咨询师"，追求"像训练有素的引导员"；共情质量单列评估，不比总分 |
| 临床证据 | 0 篇 RCT，无真人兜底，无牌照 | 明确"自助技能训练工具"定位；安全分流硬编码转介路径 |
| 商业闭环 | 无支付方、无牌照，只能被批量采购 | 不解决。只证明两件事：完成一轮五步的完成率、咨询师可读的结构化记录 |
| 依从性 | 只有对话，没有教练、社群、提醒 | 只做"单次完整闭环"，不承诺长期留存 |

## 7. 把对比做成实验：三组对照

只有对比表是文献综述，加一组对照才是方案论证。正式集在 `eval/datasets/knowledge/formal-v1.jsonl`：

| 组 | 系统 | 用途 |
|-|-|-|
| A | 通用模型直接回答 | 下界：证明"有 RAG"本身的价值 |
| B | 通用 RAG（检索片段拼上下文） | 主对照：证明"证据结构化 + 引用校验"的增量 |
| C | 本方案 | 实验组 |

专用指标：引用支持率、无依据陈述率、危机识别召回率/误报率、完成一轮所需轮次、单会话成本。
当前只跑了 4 条小样本（2 可答 + 2 应拒答），结果见 [版本记录](../06-评估/01-版本记录.md)，
**不能当统计结论**，只能证明脚本与口径可用。

## 8. 五个决定，各有一条被否掉的替代方案

| 设计决定 | 被否掉的替代 | 否掉的理由 |
|-|-|-|
| 不微调垂直模型，走通用模型 + RAG | SoulChat / EmoLLM 路线 | 微调换风格不换可靠性；指南更新要重训，而证据表只需重新入库 |
| 用状态机 + 显式字段，不用低代码平台 | Dify / FastGPT | 平台把会话建模为消息历史，表达不了"回到第 4 步只改一个字段" |
| 保留 `kb_evidence` 这张重表 | 只用 chunk + metadata | 用结构化字段替代人力审核的规模，是与 Wysa 对齐的最小代价 |
| 边界停在"不诊断" | 做筛查 / 分诊 / 风险评级 | 声明疗效即入器械监管，不声明则无护城河 |
| 模型按节点路由，不锁定单一模型 | 全流程用一个最强模型 | 延迟是硬约束，分类与抽取用规则或小模型就够 |
