# 产品与边界

## 1. 一句话定位

把 CBT 里可自助的部分做成一个**有明确步骤、有出处、有安全兜底**的工具，而不是一个会聊天的心理模型。

两个工作流，共用一个经过审核的心理知识库：

| 工作流 | 做什么 | 不做什么 |
|-|-|-|
| **知识学习** | 回答心理学、心理健康、治疗理论问题，提供出处与学习路径 | 不做个性化建议，不替代教材 |
| **CBT 自助** | 围绕一个具体困扰，走情境识别 → 自动思维 → 认知检验 → 微型行动 → 复盘 | 不诊断、不评估风险等级、不承诺疗效 |

## 2. 边界：先定边界，再定技术

| 做 | 具体含义 |
|-|-|
| 心理知识科普与学习 | 回答概念、机制、疗法适用范围，附可核对的章节/页码 |
| CBT 自助练习 | 结构化引导，每一轮的结论由用户确认后才生效 |
| 风险识别与转介 | 命中安全规则即停止普通流程，给出你所在地区的急救与心理援助路径 |
| **不做** | **临床诊断、治疗决策、药物建议、风险分级** |

"暂不做"不是保守，而是定价结构决定的：声明疗效即进入医疗器械监管（周期以年计、费用以百万计），
不声明则没有护城河。在"没有人愿意为预防付钱"的市场里，唯一站得住的位置是**当工具卖**——
卖给学校、企业、咨询机构的福利采购或课程配套。推导见 [方案对比 §产品层](03-方案对比.md)，
决策记录见 [ADR-0004](../04-adr/ADR-0004-产品边界停在不诊断.md)。

这条边界直接约束了后面的实现：不出现"抑郁程度""风险等级"，情绪自评只做 0–10 的自报刻度，
偏差标签只作候选提示，安全分流只回答"是否转介"，不回答"有多严重"。

## 3. 范围裁剪：为什么不是多 Agent

第一版不需要多个 Agent，也不需要 GraphRAG。

理由只有一条：多 Agent 与知识图谱解决的是"知识分散在多个主体、需要协商"的问题；
本项目的知识集中在一套审核过的文档里，复杂度应该花在**证据质量**与**状态可控**上，
而不是花在 Agent 之间的对话上。

由此得到两个工程约束：

1. 一个流程一个 State 类，两个流程不共享业务状态（[ADR-0005](../04-adr/ADR-0005-双Graph独立State.md)）；
2. 检索、融合、引用定位是确定性代码，模型只用在"理解问题"与"改写/总结"两处。

## 4. 谁在用

| 角色 | 关心 | 入口 |
|-|-|-|
| 使用者 | 现在能说什么、走到第几步、我说过的话去哪了 | `/room/`、`/knowledge/` |
| 咨询师 / 老师 | 这一轮发生了什么、用户确认过什么 | 记录页（可打印） |
| 运营 / 审核 | 规则改了会不会出事、内容审过没有 | `/internal/*` |
| 开发者 | 这一轮为什么这么走 | 会话轨迹、逐轮事件 |

四类人的界面不强行统一：前台是阅读与陪伴，后台是工具型控制台
（[UI 设计规范 §0](../05-规范/02-UI设计规范.md)、[界面与交互](../03-设计/04-界面与交互.md)）。
