# 提示词规范

配套 [第 7 章 提示词组织](../01-方案/07-提示词组织.md)。

## 1. 文件结构

每个 prompt 文件由"序言块 + 指令正文 + 输出契约"三段组成：

```markdown
---
prompt_id: cbt_cognitive_review
version: 1.2.0
language: zh-CN
node: cognitive_review
output_format: json
---

## 角色
（该节点扮演什么）

## 输入
（Graph 注入的字段名，逐个列出，不要写"上文"）

## 任务
（步骤化的动作）

## 约束
（禁止事项，尤其是"不得推断""不得补充证据"）

## 输出契约
（JSON schema 或字段清单 + 一个正例）
```

## 2. 版本号规则

| 变更 | 版本位 |
|-|-|
| 改输出字段、改流程步骤、增删约束 | minor +1（`1.1.0 → 1.2.0`） |
| 仅措辞、示例、标点 | patch +1（`1.2.0 → 1.2.1`） |
| 换节点职责 / 换输出格式 | major +1，且必须新增评估记录 |

## 3. 硬性约束

1. **不在 prompt 里写模型名、温度、max_tokens**：这些属于节点配置，不属于提示词。
2. **不写"请参考以上内容"**：输入必须显式列出字段名，变量用 `{{field}}`。
3. **安全规则只在 `common/safety-rules.md` 维护**，节点文件不重复抄写。
4. **涉及证据的节点必须写"证据不足时如何回答"**，且默认动作是"说不知道"，不是"合理推测"。
5. **不得要求模型输出它无法知道的东西**：如推荐强度、证据等级，只能转述原文，缺失即 `null`。

## 4. 变更流程

```
改 prompt → 跑该节点的评估子集 → 记录结果 → 通过则升版本号并提交
                                      └→ 不通过则回滚，保留改动记录
```

评估子集与指标见 [第 11 章](../01-方案/11-评估指标.md)。结果留档在 `eval/results/`（不入库）。

## 5. 命名

- 文件名：`kebab-case.md`，如 `cognitive-review.md`。
- `prompt_id`：`{graph}_{node}` 蛇形，如 `cbt_cognitive_review`。
- 文件名与 `prompt_id` 必须能互相推导，禁止出现两个名字对不上。
