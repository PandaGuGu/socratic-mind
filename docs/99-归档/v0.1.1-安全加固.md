# v0.1.1 安全与一致性加固

v0.1.0 的验收证明的是"链路能跑通"，这一版处理的是"跑通之后不能出事"。
范围：鉴权、隐私、知识闸门、安全分流、并发与状态、几处会让人卡住的实现缺陷。
**不涉及**模型质量、评估集、PostgreSQL 实跑——那几项仍未验证，见文末。

## 一、改了什么

### P0 鉴权与隐私

| 问题 | 修法 | 位置 |
|-|-|-|
| 会话 id 自增 + 接口无鉴权，可按序枚举读别人的心理记录 | 服务端签发 HMAC 匿名令牌，全部会话接口校验归属；不属于本人一律 404；id 加随机后缀 | `security/UserTokenService`、`web/CbtController`、`common/support/Ids` |
| `GET /api/cbt/sessions` 不传 userId 返回全库 | 只按令牌身份列出；无令牌 401 | `CbtController#list` |
| 内部接口默认开启且无鉴权，可改禁句/流程 | 默认关闭；开启必须配 `psych.internal.token`，否则启动失败；拦截器统一校验 | `security/InternalAuthInterceptor`、`InternalSecurityConfig`、`application*.yml` |
| 知识库 `publish=true` 直通发布，等于匿名可投毒 | 入库一律 DRAFT/REVIEWING，只有 `/review` 的 approve 才能被检索；示例语料由启动任务显式审核 | `IngestionService`、`SeedKnowledgeLoader` |

### P1 安全分流

| 问题 | 修法 |
|-|-|
| `他/她/朋友/家人` 一出现就放行，"我不想活了，他不知道"会被当普通消息 | 重写规则：本人意图 HOLD；第三人称/引用语境 → REVIEW（不暂停但必须进队列）；"他"不再是一票豁免 |
| 缺常见表达、无英文变体 | 补"想消失/不想醒来/撑不下去/活着太累"等与 `want to die` 等英文式；先抹掉"累死了/想死你了"这类程度补语 |
| 放行只写一个字符串，没人看得到 | 新增 `GET /api/internal/safety/review` 待复核队列；控制台顶部显示"待复核 N"，筛选器包含 review |
| 求助信息不可执行 | 话术改为 **12356（全国统一心理援助热线）+ 120**，并去掉"你随时可以回来"这句不成立的承诺 |
| 无任何测试 | `SafetyScreenerTest`：12 条 HOLD / 5 条 REVIEW / 6 条 PASS 用例表 |

### P2 并发与状态

| 问题 | 修法 |
|-|-|
| `save()` 三步写无事务，失败会留下"有会话没消息" | `@Transactional` |
| 并发消息互相覆盖 | `CbtFlow` 按会话分段加锁（64 段），同一会话串行 |
| 幂等表无界、不覆盖 confirm | 有界 LRU（1 万条），confirm 也纳入幂等 |
| 无长度/频率限制 | 消息 ≤ 2000 字；每用户 60 条/分钟；每 IP 30 次开新会话/小时 |
| 刷新即丢会话，库里却仍是 running | 前端持久化 session id，刷新后 `GET` + `/history` 续上 |
| 读接口与写流程并发可能 CME | `CbtSession` 四个列表改 `CopyOnWriteArrayList` |

### P3 实现缺陷

| 问题 | 修法 |
|-|-|
| 「我再改改」是死路（输入框打开了但发送被拦） | 进入编辑态后走 `/confirm` 的 `thought` 字段；后端本来支持，只是没接 |
| 默认流程缺行为实验/判断节点，配置缺失时静默少一条分支 | `defaults()` 补全拓扑；启动时对内置默认值也跑发布校验；文件缺失打 WARN |
| `advance` 用 guard<4 兜底，成环时停在无话术的 CONDITION，用户看到空白 | 显式环检测，抛 503；话术为空时给兜底文案而不是空串 |
| 模型调用无超时、无 max_tokens | 连接 5s / 读 30s / max_tokens 400；空响应显式报错 |
| 全局异常把 `e.getMessage()` 回给客户端 | 只有业务异常带文案；未预期异常记日志、回固定话术；confirm 状态冲突改 409 |
| 确认话术出现「「双重引号」」 | 平衡想法本身已带引号，确认模板去掉外层引号（配置 v7） |

## 二、验证

### 自动化

`mvn -o test`：**85 项全过**（v0.1.0 为 69 项）。新增 16 项：

- `SessionAuthTest`（4）：无令牌/伪造令牌 401、他人会话 404、列表只返回本人、带令牌复用身份；
- `InternalAuthTest`（2）：控制台与知识写入无令牌 401、持钥 200，且入库仍是 reviewing；
- `KnowledgePublishTest`（1）：`publish=true` 不产生可检索证据，approve 之后才可检索；
- `SafetyScreenerTest`（4）、`EmotionTaggerTest`（3）：规则表与情绪标签边界；
- `ConcurrentTurnTest`（1）：两条并发消息各自推进一次、都不丢；
- `FlowCycleTest`（1）：流程成环时报"存在环"，不再静默空白。

### 手工端到端（H2 档，2026-11-19）

```
POST /api/cbt/sessions                    → 200 + X-User-Token
GET  /api/cbt/sessions/{id}   无令牌       → 401
POST /api/cbt/sessions/{id}/messages 无令牌 → 401
GET  /api/cbt/sessions/{id}   伪造令牌     → 401
GET  /api/cbt/sessions/{id}   本人令牌     → 200
GET  /api/cbt/sessions        无令牌       → 401（旧实现返回全库）
```

流程与分支：情境 → 想法 → 检验 → 行动（"写下三条"）→ **BEHAVIORAL_EXPERIMENT** → 确认；
`POST /confirm` 带 `thought` 写入的是用户改过的说法：

```
confirmed= 我可能会紧张，但前三次都讲下来了
candidate= 「我肯定会搞砸」是一个预测，不是事实。…
```

安全分流：

```
"我真的不想活了"      → SAFETY_HOLD，话术含 12356 / 120
"我朋友说他不想活了"  → 正常推进，safetyStatus=review
GET /api/internal/safety/review → 两条都在队列里（hold + review）
```

控制台与知识库：

```
GET  /api/internal/overview 无令牌   → 401
GET  /api/internal/overview 有令牌   → 200（sessions/holds/pendingReview）
POST /api/knowledge/documents 无令牌 → 401
POST /api/knowledge/documents 有令牌 → status=reviewing；检索不到该文档
```

重启存活：杀进程后以同一 `PSYCH_USER_SECRET` 重启，同一令牌仍可读到 7 轮轨迹、12 条消息、
用户确认的说法。

## 三、仍未解决（不装作解决）

1. **模型层仍是桩**：生成质量、延迟、成本没有验证；`http` 档已补超时与 max_tokens，但没跑真实账单。
2. **检索仍是哈希向量**：`embedding-provider: stub`，语义检索能力未被证明；`/api/knowledge/search` 对无关查询会返回 0.016 量级的噪声命中（真实 embedding + 阈值应解决，但属于 M6 范围）。
3. **认知检验只收反例**：`evidence_for` 仍是空字段——要采集"支持证据"，需要在画布上增加一次追问（协议变更），不是纯工程改动；`emotions` 已改为"从用户原话标注情绪词"，它不是量表。
4. **M6 评估未开始**：`eval/datasets` 为空，三组对照与指标都没有数据。
5. **PostgreSQL/pgvector 未实跑**：仍用 H2 的 PostgreSQL 兼容模式验证会话域。
6. **令牌是设备级、不可迁移**：清缓存/换设备即失去旧记录；这是 ADR-0007 明确接受的代价。
7. **限流是单机的**：多实例部署要挪到网关。
