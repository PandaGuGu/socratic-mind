# Socratic Mind 一页纸概览

## 是什么

两个工作流，共用一个审核过的心理知识库：

1. **知识学习** —— 回答心理学 / 心理健康 / 治疗理论问题，每条结论指回文献页码。
2. **CBT 自助** —— 围绕一个具体困扰，走完"情境 → 自动思维 → 认知检验 → 微型行动 → 复盘"。

前端 Vue 3，后端 Java 模块化单体，工作流用 Spring AI Alibaba Graph，检索用 PostgreSQL + pgvector + 全文索引。

## 不是什么

| 不是 | 原因 |
|-|-|
| 不是心理聊天机器人 | 聊天机器人优化"说得像不像人"，本方案优化"这句话有没有出处、用户走到第几步、这句该不该说" |
| 不是诊断工具 | 不推断精神障碍、不给药物或治疗指令；声明疗效即进入医疗器械监管 |
| 不是多 Agent 系统 | 第一版两个 Graph 足够；多 Agent 与 GraphRAG 解决的是知识分散问题，这里知识是集中的 |
| 不是低代码平台能直接拼出来的 | 平台把会话建模为消息历史，本方案需要可暂停、可回滚、可确认的业务状态机 |

## 凭什么

一句话：**把 Wysa 式神经符号架构用开源 Java 栈重做，把"临床审核话术"换成"可版本化、带证据属性的审核知识库"。**

于是新增一个干预方式不需要改代码，只需要入库一份带证据属性的文档——内容生产成本从"写脚本"降到"审文档"。

代价写在明面上：没有临床团队、没有 RCT、没有牌照、没有真人兜底，共情表现大概率弱于垂直微调模型。四条短板见 [§2.6](../01-方案/02-相关方案横向对比.md)。

## 三个技术承诺

| 承诺 | 落到哪 |
|-|-|
| 出处可溯源到页码 | `kb_citation` + `verify_citations` 节点（[§4.2](../01-方案/04-RAG知识数据架构.md)、[§5.2](../01-方案/05-双Graph设计.md)） |
| 流程状态不被模型持有 | `CbtState` 显式字段 + Checkpoint + threadId（[第 6 章](../01-方案/06-交互与状态恢复.md)） |
| 证据不足就说不知道 | 条件路由"证据不足 / 来源冲突"分支（[§5.2](../01-方案/05-双Graph设计.md)） |
