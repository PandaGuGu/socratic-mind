# 文档地图

`docs/` 是方案与决策的事实来源。代码与文档冲突时以文档为准；文档之间冲突时以更新的那篇为准，
并在同一提交里改掉旧的那篇。同一个事实只允许有一个当前版本。

## 从哪开始

| 你想 | 读这个 |
|-|-|
| 五分钟知道这是什么 | 根目录 [README](../README.md) |
| 知道现在能跑到什么程度、还差什么 | [版本记录](06-评估/01-版本记录.md) |
| 接手代码 | [总体架构](01-概览/02-总体架构.md) → [模块与技术栈](02-架构/01-模块与技术栈.md) → [接口契约](02-架构/05-接口契约.md) |
| 改流程、规则或话术 | [流程与状态](02-架构/02-流程与状态.md) → [CBT 状态机](03-设计/01-CBT状态机.md) → [内部后台](03-设计/03-内部后台.md) |
| 上线与运维 | [内部后台](03-设计/03-内部后台.md) → [外部依赖约定](05-规范/03-外部依赖约定.md) → [deploy/README](../deploy/README.md) |
| 改一个架构决定 | 先读 [04-adr](04-adr/)，改决定必须新增 ADR |
| 有个词看不懂 | [术语表](术语表.md) |

## 约定

1. 每篇开头三行 front-matter：`title` / `status`（`定稿`·`草案`·`待决策`）/ `updated`。
2. 文件名即标题，不再编号章节号；文件一旦被外部引用就不要再改名。
3. 文档只写"现在是什么"。过程记录留给提交与版本记录，不往设计文档里追加"某天改了什么"。
4. 改根 README 或移动文档后，跑一次 `python scripts/check-links.py`。

历史版本与旧的走查记录不在仓库里保留副本，见 git 历史（`git log -- docs/`）。
