# 文档地图

`docs/` 是方案与决策的事实来源。代码与文档冲突时以文档为准；文档与 ADR 冲突时以**最新 ADR** 为准。

## 从哪开始

| 你想 | 读这个 |
|-|-|
| 五分钟知道这是什么 | 根目录 [README](../README.md) |
| 看现在能跑到什么程度、还差什么 | [版本记录](05-评估/版本记录.md) |
| 接手代码 | [模块拆分](01-方案/03-模块拆分.md) → [接口设计](01-方案/08-接口设计.md) → [API 契约](02-设计/API契约.md) |
| 上线与运维 | [内部后台](02-设计/内部后台.md) → [外部依赖与付费资源约定](04-规范/外部依赖与付费资源约定.md) |
| 改一个架构决定 | 先读 [03-adr](03-adr/)，改决定必须新增 ADR |
| 有个词看不懂 | [术语表](术语表.md)：RAG / 证据单元 / threadId / 神经符号 的统一口径 |

## 写文档的三条约定

1. 每篇开头三行 front-matter：`title` / `status`（定稿·草案·待决策·归档）/ `updated`。
2. 章号一旦发布不再重排；新增内容用 `03-a`、`04-b` 挂靠，避免外链失效。
3. 状态写在 [版本记录](05-评估/版本记录.md)，过程留在提交与归档里——不往设计文档里堆"某天改了什么"。
