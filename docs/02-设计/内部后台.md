# 内部后台（只读控制台）

> 入口：`GET /internal`（`psych.internal.enabled=true` 时注册）
> 读者：作者与评审，**不是用户**。本页不适用 [UI 设计规范](../04-规范/UI设计规范.md)。
> 上位依据：[§6.3 Checkpoint 不等于业务数据库](../01-方案/06-交互与状态恢复.md)、[第 8 章 接口设计](../01-方案/08-接口设计.md)、[CBT 状态机](CBT状态机.md)。

## 1. 它回答的问题

产品界面回答"这句话凭什么这么说""我刚才说了什么"；内部后台只回答一件事：**这一轮到底走到哪一步、为什么走这一步。**

参考实现是 `lcy05/cbt-agent` 的前端：它把"链路轨道"做到了极致，但 README 的已知边界里写着"拿不到完整轨迹与 State 明细，`GET /trace` 尚未实现"。本项目补的正是这块缺口，并且顺序相反——**先有事件，再有视图**，视图只是事件的投影。

## 2. 三层，顺序不能反

| 层 | 载体 | 缺了会怎样 |
|-|-|-|
| 事件 | `CbtTurnEvent`（每轮一条） | 只有字段快照，"第 3 轮为什么被拦住"永远说不清 |
| 接口 | `/api/internal/*` | 事件只在内存里，没有读取面 |
| 视图 | `/internal` 静态页 | 有数据没人看，等于没做 |

三者都齐才算"能查"；只有视图没有事件，就是摆拍。

## 3. 事件模型

`CbtTurnEvent` 与本项目已有的 `CbtMessage` 分工明确：

| | `CbtMessage` | `CbtTurnEvent` |
|-|-|-|
| 记什么 | 说了什么 | 为什么这么走 |
| 谁看 | 用户、咨询师 | 作者、评审 |
| 能否导出 | 能，属业务事实 | 不必，属运行时审计 |
| 一条消息对应 | 1 条 | 1 轮的 1 条 |

字段与取值：

| 字段 | 取值 | 说明 |
|-|-|-|
| `turnNo` | 连续整数 | 后台按它排序，不允许跳号 |
| `action` | `start` / `answer` / `blocked` / `safety_hold` / `confirm` / `end` | `blocked` 专指"被中断点或终态挡住"，与正常回答必须区分 |
| `stageFrom` → `stageTo` | `CbtStage` | 首轮 `stageFrom` 为 null |
| `safetyRule` | `self_harm` / `harm_others` / `context_guard` / null | **放行也留痕**：`context_guard` 表示命中风险词但被第三人称语境放行 |
| `modelMode` | `model` / `template` / `none` | 这一句是模型写的、模板兜底的，还是没调模型 |
| `latencyMs` | ≥0 | 端到端耗时，不是模型耗时 |
| `at` | 时间戳 | 事件时刻 |

`context_guard` 这一条是刻意的：v0.1 的安全分流是关键词 + 第三人称排除，最可能的失效方向是**漏判**（例如"他今天没回我消息，我不想活了"会被代词放行）。放行不记录，漏判就永远无法回溯；记录之后，[安全分流规则](安全分流规则.md) 的复核才有原料。

## 4. 状态推导：前端不猜

链路轨道的五种状态全部由 `trace` 与 `session` 推出来，不读文案、不做关键词匹配（这是 cbt-agent v1 契约下的妥协，不继承）：

| 状态 | 判定 |
|-|-|
| 已完成 | `stage` 在 `visited` 中（由每条事件的 `stageFrom`/`stageTo` 累加），或当前阶段已结束 |
| 进行中 | `stage === 当前阶段` 且未结束、未等你确认 |
| 等确认 | 当前阶段是中断点且 `awaitingUser === true` |
| 未进入 | 既不是当前阶段，也不在 `visited` 中 |
| 安全暂停 | 当前阶段是 `SAFETY_HOLD`，用 `--refer` 标红 |
| 未走这条 | 只用于干预决策下的分支：`taken` 由 `interventionType` 字段直接给出 |

两个细节来自 cbt-agent 的正确做法：**"未走这条"必须与"未进入"区分**（否则用户以为漏了一步）；**分支同目标只标一条**（避免"两条都走了"的错觉）。

## 5. 诚实标识

顶栏三个徽章不是装饰，是防止演示被误当成生产：

| 徽章 | 来源 | 为什么必须显示 |
|-|-|-|
| 内存档 · 重启即丢 | 存储实现的类名 | 现在所有会话与轨迹都在 `ConcurrentHashMap` 里 |
| 桩模型 | `psych.ai.provider` | 桩模型不会生成自由文本，`modelMode` 会全部落成"模板兜底" |
| 无鉴权 · 仅本机 | `psych.internal.auth` | 接口没有认证，不能对外 |

## 6. 只读边界

- 不提供任何改写业务状态的接口；用户确认仍然只能走 `POST /api/cbt/sessions/{id}/confirm`。
- "生成演示会话"调用的是**真实流程**：脚本化的只是输入消息，轨迹与字段由 `CbtFlow` 真实产生。页面对这类会话标「演示」。
- 页面可以复制 JSON，但不提供删除、导出、重跑。

## 7. 开关与部署

```yaml
psych:
  internal:
    enabled: true   # false 时 /internal 与 /api/internal 都不注册
    auth: false     # 仅用于在界面上诚实显示"无鉴权"
```

对外部署必须置 `enabled=false`；它没有登录、没有速率限制，只允许本机或可信内网访问。

## 8. 已验证（2026-11-17）

- `mvn test`：全仓 59 项通过，其中 `psych-app` 41 项（轨迹 7、提示词 4、守卫规则 9、发布校验 7、画布执行 3，其余为既有链路），`psych-infrastructure` 10 项（守卫装饰器 5 + 策略存储 5）。
- 本机启动后 `GET /internal` 200；两条演示会话（流程 / 安全）在页面上可完整回溯。
- 顺手修掉一个语义缺陷：`CbtFlow` 走到 `SESSION_SUMMARY` 后不再推进，但 `SessionView.status` 只看 `stage.isTerminal()`，导致已结束的会话长期报 `running`。现在"总结"也算结束。

## 10. 输出策略：让运维改规则，而不是改代码

### 10.1 问题

在此之前，"模型这句话能不能出去"由三处代码决定：`CbtFlow` 的长度判断、`SafetyScreener` 的正则、`RagService` 的引用校验。运维想加一条禁句、想临时放松长度，只能提需求、等发版。**规则的所有权在开发手里，是这套系统最不"可运营"的地方。**

### 10.2 形状：一个装饰器 + 一份 JSON + 一个页面

```
CbtFlow / RagService
      │  chat(system, user, "cbt_balance")
      ▼
GuardedChatPort          ← 所有模型调用的唯一闸门
      ├── OutputPolicyStore   读 JSON、按 mtime 热加载、坏文件不生效
      ├── GuardRules          纯函数：长度 / 禁句 / 与输入重合度
      └── GuardAuditLog       最近 200 条：通过 / 重写后通过 / 拦截
      ▼
StubChatPort / HttpChatPort
```

页面：`/internal/policy.html`。改开关、改阈值、加减禁句、粘贴一段输出"试一下"，保存即热加载，不需要重启。

### 10.3 运维能改什么

| 控制项 | 作用 | 边界 |
|-|-|-|
| 档位总开关 | 故障时一键放行（止血） | 关掉即完全不设防，页面上会标"已关闭" |
| 最短 / 最长字数 | 挡住截断与长篇大论 | 0 表示不限 |
| 禁句表 | 说教、安慰套话、感叹号、诊断词 | 子串匹配，不做语义判断 |
| 重合度阈值 | 挡住"凭空加戏"：输出里的内容二连字有多少能在输入里找到 | 启发式，不是事实核查 |
| 违规后重写次数 | 带违规原因让模型重写，0–3 次 | 仍是模型生成，可能再次违规 |
| 保存 / 版本 | 每次保存 version+1，带 updatedBy | 历史靠 git，不做应用内版本树 |

命中后的处理是固定的：**能重写就重写，重写还不过就退回模板**。用户永远不会看到被拦下的那句。

### 10.4 三个刻意的设计

1. **规则即数据，不是常量。** 策略文件默认为 `config/output-policy.json`，可以直接进 git：改动有 diff、能 review、能回滚。页面上改的和文件里写的是同一份东西。
2. **坏文件不生效。** 解析或校验失败时保留内存中的上一版并告警——避免一次手滑把全部档位关掉。
3. **拦截必须留痕。** 每一次拦截同时进两处：轮次轨迹的 `guardRule`（这一轮为什么用了模板）与守卫审计（这条规则一共拦了多少次）。只看其中一处，都会得到片面的结论。

### 10.5 与 LangGraph / 可视化编排的区别

经常被问到"为什么不做成拖拽连线"。因为这是两类东西：

| | 流程编排（图） | 输出策略（规则） |
|-|-|-|
| 谁改 | 开发 | 运维 / 内容 |
| 改什么 | 有哪几步、怎么走 | 这一步说的话能不能出去 |
| 出错代价 | 流程跑不通，测试能发现 | 用户看到不该看的话 |
| 合适的形式 | 代码 + 图（只读展示） | 表单 + 开关 + 测试框 |

LangGraph Studio 那类界面是**开发调试器**：跑图、看状态、改 state，面向写代码的人，不是运维改内容的配置台。真正对应"运维控制模型产出"的业界形态是 guardrails 层（规则即配置 + 运行时拦截），本项目实现的是其中最小可用的一套。

### 10.6 当前边界

- [ ] 只能控"规则"，不能控"话术"：兜底模板仍在代码里，运维改不了措辞。
- [ ] 不能控提示词：`prompts/cbt/stages.md` 仍是版本资产（`PromptAssetTest` 锁结构）。
- [ ] 不能控流程：节点与边仍是代码。把它们变成数据会丢掉编译期检查与现有测试，收益不成正比。
- [ ] 重合度是词面启发式，同义改写会被误判为"编造"——误判的代价是退回模板，可接受。
- [ ] `rag_answer` 档位默认关闭：知识问答已有引用校验，避免两层规则互相盖住。

## 11. 流程画布：能拖、能改、能发布

### 11.1 一句话

`/internal/flow.html` 把 CBT 的八个阶段画成一张图：节点可以拖动摆位，点开能改话术、去向、模型档位、干预关键词，发布后下一轮立即生效。**不是截图，是真在改执行。**

### 11.2 分层：定义、校验、执行

```
flow.html ──PUT──▶ FlowParamsStore ──校验──▶ FlowValidator
                        │
                        └─热加载─▶ CbtFlow（ask / advance / modelEnabled / classify）
```

- **FlowDefinition**：一份 JSON（`config/flow-params.json`），节点 id 固定为八个阶段；
- **FlowValidator**：替代编译期检查的发布闸门；
- **CbtFlow**：话术、去向、模型开关、关键词全部从定义读，代码只保留"这一步写哪个字段"。

### 11.3 能改 / 不能改

| 能改 | 不能改 |
|-|-|
| 每个节点的标题与话术（支持 `{{thought}}`、`{{plan}}`） | 核心节点的存在：八个阶段是主干，删不掉 |
| 节点位置（拖动即保存） | 字段语义：谁写 `targetProblem`、谁写 `candidateThought` 是代码定的 |
| 每步是否调模型（`none` / `cbt_balance` / `cbt_summary`） | 安全分流：不在画布上，每轮硬跑 |
| 下一步（在允许集合内） | 确认中断不能被绕过：分支只能指向白名单节点 |
| 分支：干预决策可按干预类型分到行为实验 / 问题解决 / 判断节点 | 分支目标必须存在且在白名单里 |
| 增删节点：右键空白处就地放置，右键节点插到它后面 / 某条分支之前 | 每种可选节点最多一个实例 |
| 判断节点的条件（干预类型、是否已确认、兜底）与去向 | 条件不开放"让模型判断" |

| 干预类型关键词表（决定行为实验 / 认知重构 / 自我观察） | 输出策略本身（那是另一页） |

### 11.4 为什么分支只能连到白名单里的节点

现在画布已经支持真分支：干预决策可以按干预类型分成「行为实验 / 问题解决 / 判断」三条，判断节点自己再按条件（是否已确认、干预类型、兜底）导向不同节点。分支在运行时真的会被求值——不是画着好看。

但**目标仍然受白名单约束**，因为每个节点写的是不同的类型化字段：情境写 `targetProblem`、想法写 `automaticThought`、检验写 `candidateThought`。把"检验"连回"想法"，证据就会覆盖自动想法；连到"总结"，候选说法永远为空。

Dify 的节点是自包含函数，连错只是跑错；这里的节点是状态机的步骤，连错会产生**空字段**和**不可解释的记录**。所以给出的是"可选集合"，不是任意连线。

### 11.3.1 怎么加节点

不再有顶栏下拉。所有增删都在画布上：

| 操作 | 结果 |
|-|-|
| 右键节点 → 「插到它后面」 | 新节点继承它的下一步，串进当前链路 |
| 右键有分支的节点 → 「插到「X」前面」 | 新节点插在那条分支的目标之前 |
| 右键空白处 → 选节点类型 | 就地放置，再自己接上 |
| 右键节点 → 「给它加一条分支」 | 直接跳到右侧分支编辑器 |
| 右键可选节点 → 「删除这个节点」 | 断开所有指向它的边并删除 |

插完立刻能看到提示，例如「已插入「行为实验」：行动 → 行为实验 → 确认」。

### 11.4.1 判断节点怎么用

判断节点不提问、不写字段，运行到这里立即按顺序求值分支，然后继续走：

```
行动（捕获行动计划、按关键词判定干预类型）
  ├─ intervention=behavioral_experiment → 行为实验 → 确认
  ├─ intervention=self_monitoring       → 判断 ─┬─ confirmed     → 复盘
  │                                              └─ else          → 确认
  └─ else                               → 确认
```

兜底分支必须存在且放在最后，否则某个条件下会无路可走——这条由 `FlowValidator` 强制。

### 11.5 发布前的四类校验

| 类 | 规则 | 失败例子 |
|-|-|-|
| 结构 | 核心八节点齐全、去向与分支目标在白名单、能从情境走到总结 | 把"检验"连到"总结"；判断节点缺兜底 |
| 语义 | 模型档位只能绑在对应阶段 | 给"情境"绑 `cbt_balance` |
| 文案 | 非空、≤1200 字、占位符必须认识 | `{{thougt}}` 拼错会原样漏给用户 |
| 枚举 | 干预类型的键必须齐全、关键词 ≤20 个且 ≤12 字 | 删掉 `self_monitoring` 这个键 |

校验不过就不落盘，页面上直接给原因——和 Dify 的"发布检查"是同一个位置，只是规则换成了这个领域的。

### 11.6 当前边界

- [ ] 可选节点每种只能有一个实例（会话状态按节点类型存），还不能摆两个判断节点做串联判断。
- [ ] 没有"试跑"：改完只能发布后再开会话看效果；输出策略页有"试一下"，画布还没有。
- [ ] 没有回滚：版本号会涨，但历史靠 git，不提供"回到 v3"。
- [ ] 话术改动没有专业复核流程：改完即生效，适合内部工具，不适合临床上线。
