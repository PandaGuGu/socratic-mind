# 安全分流规则

> 上位文档：[§5.3 CbtGraph](../01-方案/05-双Graph设计.md)、[ADR-0004](../03-adr/ADR-0004-产品边界停在不诊断.md)。
> **本文是 M4 的阻塞项**：规则不成文，代码无从实现。

## 1. 设计立场（已定）

| 已定 | 说明 |
|-|-|
| 只做"是否转介"，**不做风险等级** | 评级是诊断的边缘形式，误报成本极高（ADR-0004） |
| 双通道：规则 + 语义 | 规则保证确定性召回，语义补模糊表达 |
| 触发即暂停普通流程 | 不继续 CBT 步骤，不追问细节 |
| 转介走硬编码资源 | 12356（全国统一心理援助热线）/ 120 / 精神科门诊 |
| 每轮入口都跑 | 不是只跑首轮（[CBT状态机](CBT状态机.md) §3.4） |

## 2. 规则通道（待定，需专业人员参与）

| 类别 | 示例 | 动作 |
|-|-|-|
| 明确危险信号 | 自伤/自杀计划、时间地点方式、告别性表达 | 立即转介 + 停止流程 |
| 模糊表达 | "活着没意思""撑不下去了" | 语义通道判断，偏保守 |
| 误报场景 | 引用歌词/新闻、学术讨论、第三人称叙述 | 不得触发 |

**待决策：误报场景的处理。** 当前倾向：误报可以接受"温和确认一句"，但**不得**直接弹转介卡片；否则系统会退化成"谁都不敢聊"。

## 3. 语义通道

- 输入：本轮用户消息 + 上一轮摘要（不带全量历史，控制延迟）。
- 输出：`normal` / `referral` + 一句理由（内部留档，不展示给用户）。
- 模型只做分类，**不生成话术**；话术来自固定模板，避免临场发挥。

## 4. 输出（对用户）

1. 一句共情式承接；
2. 明确说明"这超出我能提供的帮助范围"；
3. 给出至少两条可立即使用的求助路径（热线 + 就近精神科/急诊）;
4. 不追问、不分析、不给建议。

## 5. 待决问题

- [ ] 规则清单的最终条目（需专业人员评审）
- [ ] 模糊表达的判定阈值与保守程度
- [ ] 触发后是否允许开新会话（见 [CBT状态机](CBT状态机.md) §4）
- [ ] 是否记录触发事件用于评估（涉及隐私与合规，倾向记录"是否触发"，不记录原文）
- [ ] 危机回应话术的模板由谁定稿

## 6. 评估要求

必须在安全测试集上同时报**召回率与误报率**（[第 11 章](../01-方案/11-评估指标.md)）。只报召回等于鼓励过度拦截。

## 7. 已实现（v0.1.2，2026-11-19）

规则不再写死在代码里：`config/safety-rules.json` 由后台 `/internal/settings.html` 编辑，
保存即热加载。执行器仍是 `SafetyScreener`，校验器是 `SafetyRulesValidator`。

| 项 | 现状 |
|-|-|
| 规则来源 | 配置文件（默认 6 条：2 条 hold、2 条 context、1 条 signal、1 条 ignore），后台可新建、删除、改启停 |
| 发布门禁 | 结构校验 + 可编辑用例表回放（默认 11 HOLD / 3 NOT_PASS / 4 PASS）；至少 1 条启用的 hold 规则；用例表下限 5 HOLD / 2 PASS |
| 规则通道 | 自我伤害、伤害他人；补"想消失 / 不想醒来 / 撑不下去 / 活着太累"与英文式 |
| 口语排除 | 先抹掉"累死了 / 想死你了 / 气死了"这类程度补语与亲昵用法，再匹配 |
| 第三人称 / 引用 | **不再一票放行**：语境指向他人或引用时置 `review`，进入待复核队列（`GET /api/internal/safety/review`） |
| 本人意图优先 | 同一句里既提到他人又表达了自己（"我妈不想活了，我也不想活了"）→ HOLD |
| 语义通道 | **未实现**（当前只跑规则） |
| 触发后 | 阶段置 `SAFETY_HOLD`，回复固定转介话术，不追问，后续消息不恢复普通流程 |
| 转介内容 | 12356（全国统一心理援助热线）+ 120；只给路径，不给等级 |
| 版本与回滚 | 每次保存留快照（`config/history/safety/v<n>.json`），回滚生成新版本 |

已验证：`SafetyScreenerTest`（默认规则）+ `SafetyRulesStoreTest`（改宽通过 / 改窄被拒 / 回滚）
+ `SettingsApiTest`（HTTP 层同样如此）。

**必须承认的局限：** 规则与用例都来自工程常识而非临床审核；用例可改，所以"基线"最终仍由人来定，
只是不能删空。改宽没有上限（误报只能靠复核实测）。语义通道、安全测试集上的召回/误报双指标、专业复核，
仍是上线前的硬门槛。
