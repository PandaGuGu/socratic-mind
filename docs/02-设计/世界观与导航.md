# 世界观与导航设计

> 原型：[frontend/preview/world-demo.html](../../frontend/preview/world-demo.html)（可直接点：点小人说话 → 纸片飞出窗外 → 点窗看过往）。
> 视觉 token 沿用 [UI 设计规范](../04-规范/UI设计规范.md)，只换空间与叙事。
> 上位依据：[ADR-0004 不诊断](../03-adr/ADR-0004-产品边界停在不诊断.md)、[§5.3 CbtGraph](../01-方案/05-双Graph设计.md)。

## 1. 一条原则：房间是家，泡泡是产物

**默认界面是房间，不是星图。** 用户打开产品，看到的是同一间屋子、同一个坐在墙角的人；窗外一开始是空的。

这条顺序不能反，理由有三条：

| 理由 | 说明 |
|-|-|
| 没有"选哪个"的决定成本 | 星图当首页时，用户每次都要先判断"我今天要进哪个泡泡"，这是一次额外的认知负担 |
| 空状态不尴尬 | 新用户面对一张空星图会以为产品坏了；面对一间空房间，只是"还没聊过" |
| 泡泡因此获得含义 | 泡泡不是系统生成的条目，而是**你说过的话堆积出来的东西**——这让"星图"变成回忆，而不是任务列表 |

一句话：**房间是入口，窗外是记忆。** 用户永远从"现在"进入，从"过去"回看。

## 2. 三层空间与数据映射

| 界面元素 | 隐喻 | 对应的数据 | 说明 |
|-|-|-|-|
| 房间 | 家 | 无（常驻） | 全局唯一；不随会话切换 |
| 小人 | 引导者 | `CbtGraph` 当前节点 | 无面孔、无名字、不拟人化称呼。它在，但不主动开口 |
| 纸片 | 一句话 | 本轮 `pendingQuestion` + 选项 | 点小人才出现；一次只出现一张 |
| 飞出的纸片 | 说出去的话 | 一条 `cbt_message`（role=user/assistant） | 每次发言都离开房间，房间因此永远是干净的 |
| 窗外的光点 | 一句话留下的痕迹 | 同上，聚合展示 | 每句话在窗外点一颗小星 |
| 泡泡 | **一次对话**（从坐下到离开） | `cbt_session` 一行 | 轮次越多，泡泡越大 |
| 丝线 | 同一主题 | 共享 `targetProblem` / 标签的会话 | 见 §3 |
| 地上的石子 | 五颗石 | `currentStage` | 8 个内部节点压缩成 5 个可见阶段 |
| 门 | 门 | 结束这一轮 | 随时可走；离开不是失败 |
| 窗 | 窗外 | 历史 | 点开才看，不主动推送 |

### 2.1 一间房，还是每件事一间房

**一间房。** 所有对话都发生在同一间屋子里。

理由：多房间意味着"我要去哪个房间"——这又回到了选择成本。而且多房间会让"同一个墙角的人"变成一个 NPC 集合，削弱"它一直在"的感觉。不同的"事"由窗外的泡泡承载，不由房间承载。

### 2.2 房间不堆积，是这套设计的核心

传统聊天界面里，40 条历史消息压在屏幕上，本身就在传递"你欠了很多"。房间的逻辑相反：

> 说出去的话会飞走。房间永远只有当前这一张纸。

代价是：用户不能在房间里往回翻。所以窗必须随时可点，且翻到的内容必须能定位回"那一刻"（时间、阶段、引用）。

## 3. 丝线表示什么

丝线必须有语义，否则就是装饰。第一版只允许一种：**同一主题**。

| 候选 | 结论 |
|-|-|
| 时间顺序（相邻相连） | 否。会连成一条链，像进度条，失去"回忆是散的"这种感觉 |
| 同一主题（共享标签） | **采用**。用户自己也能看懂：「这两件事其实是一件事」 |
| 因果/情绪关联 | 暂缓。需要模型判断，且涉及对用户心理状态的推断，与 [ADR-0004](../03-adr/ADR-0004-产品边界停在不诊断.md) 冲突 |

因此：**宁可稀疏，不要画成蜘蛛网。** 全部连通的图等于没有信息，而且看起来更乱。

## 4. 视觉编码的禁区

| 禁止 | 原因 |
|-|-|
| 泡泡大小表示"严重程度" | 变相分级，违反 ADR-0004 |
| 颜色表示情绪（红=愤怒、蓝=低落） | 同上；情绪是私密信息，不该被系统"标注" |
| 长期未处理的泡泡枯萎 / 熄灭 | 制造内疚，与产品定位相反 |
| 未读红点、待办角标 | 把陪伴变成 KPI |
| 泡泡被"删除"的动画 | 会被理解为"这段经历被抹掉了" |

允许的编码只有三种：

- **大小** = 这次对话的轮次（投入，不是严重度）
- **亮度** = 是否还在进行（进行中的泡泡有稳定微光）
- **虚实** = 虚线表示"这一轮的泡泡还没成形"

## 5. 安全转介：人不能开口说"我帮不了你"

这是最容易做错的一处。如果让墙角的人说出"这超出我的范围，请拨打…"，用户接收到的是**"陪我的人拒绝了我"**。

正确做法是**让人沉默，让房间说话**：

| 元素 | 变化 |
|-|-|
| 小人 | 停止呼吸动画，仍在原处，不消失、不背对 |
| 窗外的光 | 由暖转冷 |
| 门边 | 亮起一盏小灯 / 出现一部电话的剪影 |
| 纸片 | 换成固定的转介纸（热线、就近门诊），不再有输入行 |

原则一句话：**"人没走，是房间把门打开了。"**

## 6. 引用在房间里怎么放

房间里不出现证据栏，否则又变回密集界面。引用降级为**纸片角上的一枚书签**：点开是一张更小的纸（来源、章节、页码），看完即收。

这仍是 [UI 设计规范](../04-规范/UI设计规范.md) §6.2 的脚注制，只是折叠了一层：**证据必须在，但不必同时全部在场。**

## 7. 熵控制

窗外虽不主动出现，但用得久了仍会满。三条规则：

1. **上限**：默认显示最近 12 个泡泡；更早的收进"更早"——一个稍大的半透明泡泡，点开后是原来的若干个。
2. **漂移**：30 天未进入的泡泡向外、变暗，但**不消失**。
3. **位置稳定**：坐标由 `sessionId` 哈希确定性生成（或首次生成后落库）。刷新、换设备都不移动。**位置一变，空间记忆就废了**，这是这类界面的生命线。

## 8. 必备的降级路径

| 需要 | 做法 |
|-|-|
| 无障碍 | 窗外提供等价的语义列表（时间 + 主题 + 阶段），读屏可遍历 |
| 不接受隐喻的用户 | 设置里切「列表模式」，回落到 [ui-demo.html](../../frontend/preview/ui-demo.html) 那种三栏界面；两种模式共用同一份数据 |
| 低性能设备 | 关闭浮动与粒子，静态星图 |
| 首次使用 | 第一屏只给一句提示（"点它一下，或者直接说想说的"），第三次进入后不再显示 |

## 9. 落地顺序

| 阶段 | 做什么 | 为什么这个顺序 |
|-|-|-|
| M5-α | 房间 + 小人 + 纸片 + 石子 | 核心体验在这里；做砸了整个概念就塌 |
| M5-β | 飞出的动画 + 窗外光点 | 纯表现层，"不堆积"这件事需要它才成立 |
| M5-γ | 窗外泡泡 + 纸片回看 | 记忆层；没有它，房间就是个不能回头的聊天框 |
| M5-δ | 丝线 + 聚合 | 锦上添花，数据量不够时反而不该做 |

**不要先做星图。** 它对入口的贡献有限，却最容易做成炫技。

## 10. 待决

- [ ] 一次对话的边界：以"点门离开"为界，还是以"静置 30 分钟"为界
- [ ] 同主题的多次对话：合并成一个泡泡，还是保留多个 + 连线（当前选后者）
